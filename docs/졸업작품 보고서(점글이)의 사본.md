## **제 1 장 서론**

#### **1.1 연구 배경**

 시각장애 수험생이 수능을 준비하고 응시하는 과정은 비장애 수험생의 학습 환경과 구조적으로 상당한 차이를 보인다. 가장 먼저, 시각장애 수험생은 점자를 촉각으로 읽거나 스크린리더를 이용해 음성으로 정보를 탐색하는데, 이러한 방식은 기본적으로 **선형적(linear) 정보 처리 방식**이기 때문에 문서의 전반적 구조, 문단 간 관계, 그래프·표·도형과 같은 비선형 시각 요소를 직관적으로 파악하기 어렵다. 선행연구에 따르면 점자 읽기 속도는 일반 시각 자료 읽기 속도의 **2\~3배 이상 느린 것으로 보고되며**, 문제 간 이동이나 세부 정보 탐색 과정까지 포함하면 전체 정보 처리 효율은 더욱 떨어진다. 이러한 특성은 실제 수능 응시 상황에도 영향을 미쳐, 시각장애 수험생은 교시별 시간 연장에도 불구하고 시험 전체가 **최대 12\~13시간**에 이르는 장시간 평가로 경험된다. 결과적으로 시각장애 수험생은 동일한 문제를 해결하기 위해 일반 수험생보다 훨씬 높은 피로도와 인지적 부담을 감수해야 한다.

둘째, 시각장애 수험생의 학습권을 더욱 제약하는 요인으로 **교재 점역 지연** 문제가 있다. 일반 수험생이 수능특강과 EBS 연계 교재를 3월 초에 받아 학습을 시작하는 반면, 시각장애인용 점자·텍스트 변환본은 제작 인력·예산·출판 구조의 한계로 인해 **수능 2\~6개월 전**에야 제공되는 경우가 빈번하다. 실제 보도에서도 EBS 점자 교재가 **9\~10월**에 완성되어 제공된 사례가 확인되었으며, 이는 시각장애 수험생이 일반 수험생 대비 **최소 4\~6개월 학습 시작이 늦어지는 구조적 격차**를 초래한다. 점역 교재의 제공 시점 지연은 단순한 편의성 문제가 아니라, 대학 입시에서 결정적인 비중을 지니는 수능 대비 과정 전체에 **지속적이고 누적된 학습 불리함**을 야기한다.

셋째, 시각장애 수험생의 학습에서 가장 큰 어려움으로 지적되는 영역은 **그래프·표·도형과 같은 비시각적 시각 정보의 접근성 부족**이다. 국어와 영어에서는 지문의 구조적 흐름이나 선택지 논리의 비교가 어렵고, 수학에서는 함수 그래프, 통계 자료, 도형 정보가 점역 과정에서 **누락되거나 설명형 텍스트로 대체**되기 때문에 원본 문제의 정보량·정확도를 확보하기 어렵다. 기존 점자 교재는 그래프의 형상을 점묘 방식으로 단순 제시하거나 음성 설명에 의존하기 때문에, 좌표·기울기·교점·증감 구간 등 문제 해결에 핵심적인 정보가 **의미 단위별로 구조화되어 제공되지 못하는 한계**가 존재한다. 이는 수학 영역에서의 성취도 격차를 심화시키는 주요 요인으로도 알려져 있다.

마지막으로, 이러한 복합적 제약은 시각장애 수험생의 학습 과정 전반에서 **비장애 수험생 대비 지속적인 학습 격차**를 발생시킨다. 동일한 교재가 늦게 제공되고, 같은 정보를 처리하는 데 시간이 더 오래 걸리며, 시각 정보 기반 문제(그래프·표·도형)를 이해하기 위해 더 많은 인지적 부담을 필요로 한다. 나아가 학습 과정에서 오답 관리, 복습 계획, 핵심 정보 재탐색과 같은 메타인지적 학습 전략을 실행하는 것도 어렵기 때문에, 시각장애 수험생은 단순한 정보 접근의 문제를 넘어 **체계적 학습 전략 형성 자체가 제한되는 교육적 불평등**을 경험하게 된다.

이처럼 수능 대비 학습 환경에서 시각장애 수험생이 겪는 문제는

**① 정보 처리 속도 격차,**

**② 교재 접근 시점 지연,**

**③ 시각 정보 접근 불가,**

**④ 학습 구조화 시스템 부재**

로 요약되며, 이는 단순한 편의·지원의 차원을 넘어 **학습권·평등권 차원에서 해결되어야 할 핵심 문제**이다.

#### **1.2 문제 상황**

수능 대비 학습에서 핵심이 되는 EBS 수능특강 교재는 매년 동일한 PDF 형식으로 제작·배포되며, 이 PDF 구조는 본질적으로 **시각적 배열(레이아웃)에 강하게 의존**한다. 지문, 문항 번호, 선택지, 그래프, 표, 각주, 이미지 블록이 한 페이지 안에서 시각적 구획과 공간적 배치를 기준으로 조직되어 있기 때문에, 이 구조를 그대로 점자나 텍스트 기반으로 변환할 경우 **정보의 상대적 위치·계층·논리 흐름이 크게 손실되는 구조적 문제가 발생**한다. 즉, 수능특강 PDF는 비주얼 중심으로 설계되어 있어 시각장애 수험생이 사용하는 비선형 정보 처리 방식(점자·음성 기반)과 근본적으로 정렬되지 않는다.

첫 번째 문제는 **PDF 기반 교재 구조의 비선형 변환 어려움**이다. 수능특강 PDF는 텍스트와 이미지, 그래프, 문항 박스, 선택지 배열이 페이지 단위로 혼재되어 있으며, PDF 내부의 레이어나 블록 구분도 시각적 배치 중심이기 때문에, OCR을 수행하거나 텍스트 레이어를 추출하더라도 원본의 의미 구조가 보존되지 않는다. 예를 들어 지문 옆에 배치된 도표, 문항 하단의 선택지, 페이지 우측의 해설 인용문 등이 하나의 긴 텍스트로 이어져 추출되면서, **지문–문항–그래프 간 연계 정보가 완전히 선형화되어 버리는 문제**가 나타나게 된다.

두 번째 문제는 **점역본으로 변환되는 과정에서 발생하는 구조 손실**이다. 현재의 점역 방식은 대부분 “시각 자료를 점자 텍스트로 일대일 치환하는 방식”에 머물러 있어, 원본 PDF의 레이아웃 중심 정보(구조, 위치, 비교 관계, 탐색 경로)가 사라지게 된다. 이로 인해 지문의 단락 구분이 모호해지고, 문항 번호와 선택지의 시각적 종속 관계가 무너지며, 그래프·표의 좌표 관계나 데이터 간 비교 구조는 텍스트 설명 한두 문장으로 대체된다. 특히 수학 문제의 그래프·도표·도형은 점자 변환 과정에서 **좌표의 방향성, 기울기, 값의 비율, 데이터 간 관계 정보가 삭제되거나 단순 나열로 대체되는 오류**가 반복적으로 보고되고 있다. 이처럼 점역 과정에서 발생하는 구조 손실은 시각장애 수험생에게 원본과 동일한 정보 구조를 제공하기 어렵게 만들어, 학습 효율과 문제 해결 전략 형성 모두에 부정적 영향을 미친다.

세 번째 문제는 **기존 스크린리더·OCR 기술의 한계**이다. 스크린리더는 문서를 순차적으로 읽는 선형 탐색 모델을 사용하기 때문에, 페이지 전체 구조를 한 번에 파악하거나, 그래프·표·도형·선택지 등 비선형 정보를 의미 단위로 재구성하는 기능이 없다. OCR 기술 역시 텍스트 인식률은 향상되었지만, PDF 내부의 의미적 블록(문단, 캡션, 그래프 축, 범례, 선택지 구조)을 추출해 “학습에 필요한 형태로 재배열하는 기능”은 지원하지 않는다. 결과적으로 시각장애인은 지문을 찾기 위해 문서 상단부터 끝까지 순차적으로 들으며 탐색해야 하고, 특정 문장이나 근거 위치를 빠르게 찾지 못하며, 그래프·표는 단순 설명 문구에 의존해 문제 해결을 시도해야 한다. 이는 수능과 같이 **시간 압박과 구조 기반 사고가 필요한 시험 환경에서 결정적 불리함으로 작용한다.**

요약하면,  
 **① 시각적 배열 중심의 PDF 구조**,  
 **② 점역 과정에서의 구조 파괴**,  
 **③ 스크린리더/OCR의 선형적 정보 처리 한계**  
 이 세 가지는 서로 맞물려 시각장애 수험생의 수능 대비 과정에서 **정보 손실·탐색 비효율·학습 격차**를 초래하는 핵심 문제로 작용한다. 기존 접근성 기술은 이 구조적 문제를 해결하기에 본질적 한계를 가지며, 따라서 원본 PDF를 기반으로 **지문·문항·그래프·선택지·표**를 의미 단위로 재구성해 점자·음성으로 제공하는 *새로운 정보 구조화 시스템*이 요구된다.

#### **1.3 연구 필요성**

시각장애 수험생의 수능 학습 환경에서 가장 근본적인 문제는 **정보 접근성의 시차와 구조적 손실**에 있다. 수능특강과 같은 핵심 교재의 점역본이 수개월 뒤에 제공되는 현실은 시각장애 학생의 학습 시작 시점을 본질적으로 지연시키며, 이로 인해 학습 기간·훈련량·문제 노출 빈도에서 비장애 학생과 심각한 격차가 발생한다. 그러나 이러한 문제는 단순히 점역 교재의 제작 속도를 개선하는 것만으로는 해결될 수 없다. 시각장애 수험생의 학습 과정에서 발생하는 핵심 어려움은 **원본 자료의 구조가 파괴된 채 제공된다는 점**이며, 이는 현재의 점역 기술·스크린리더·lOCR 방식이 가진 구조적 한계에서 비롯된다. 따라서 기존 방식과는 다른 패러다임의 접근성 기술이 요구된다.

첫째, **실시간 접근성 변환 기술의 부재**는 시각장애 수험생에게 제공되는 학습 자료의 양과 질을 제한하는 가장 큰 요인이다. 현재 대부분의 점자 교재는 전문 기관의 수작업 점역에 의존하고 있으며, 그래프·표·도형·문항 배치와 같은 시각 중심 자료는 점역 과정에서 단순 텍스트로 대체되거나 누락되는 경우가 많다. 더 나아가 점역본이 제공되기까지의 시간 지연으로 인해, 시각장애 수험생은 매년 변화하는 수능 출제 경향을 즉시 반영하여 학습하기 어려운 구조적 불이익을 겪는다. 이를 해소하기 위해서는 원본 PDF가 공개되는 즉시, **자동으로 점자·음성 기반의 대체 가능한 구조로 변환해 제공하는 시스템**이 필수적이다. 즉, 시각장애 수험생이 비장애 수험생과 동일한 시점에 동일한 학습 자료에 접근할 수 있도록 하는 *실시간 접근성 변환 기술*이 새로운 교육 형평성의 핵심 요소로 부상하고 있다.

둘째, 시각장애 수험생에게는 기존 점자 교재나 스크린리더가 제공하지 못하는 **비선형 정보 제공 모델**이 필요하다. 일반적인 텍스트 기반 접근성 기술은 문서를 위에서 아래로 순차적으로 읽어나가는 선형 처리 방식에 기반하기 때문에, 복잡한 개념을 구조적으로 이해하거나 특정 정보를 빠르게 탐색하는 데 적합하지 않다. 반면, 수능 지문·문항·그래프는 원래 \*\*비선형적 구조(문단 구조, 근거 위치, 선택지 간 비교 관계, 그래프의 의미 요소 등)\*\*를 기반으로 이해해야 하는 자료이다. 이러한 비선형 구조가 점자 변환 과정에서 사라지고 단순한 선형 텍스트로 대체되면, 시각장애 수험생은 문제 해결 과정에서 필요 이상의 시간과 인지적 부담을 겪게 된다. 그럼에도 불구하고, 현재 시각장애인 접근성 연구는 대부분 읽기 순서를 단순 통제하거나 음성 출력을 개선하는 수준에 머물러 있어, **문서의 의미 구조를 재조직하고 학습자가 원하는 단위로 탐색할 수 있게 하는 비선형 정보 모델**은 사실상 부재한 상황이다.

셋째, 그래프·표·도형과 같은 시각 기반 정보는 점자·음성 변환의 난이도가 매우 높아 기존 기술로는 해결이 어렵다. 그래프의 좌표·교점·증감 패턴·최대·최소 등 문제 해결에 필수적인 요소는 단순한 음성 설명이나 점자 나열만으로는 명확히 전달될 수 없다. 이러한 정보는 **‘의미 단위별로 추출–압축–구조화’하는 새로운 알고리즘적 접근**이 필요하며, 실제 교육 현장에서도 시각장애 학생이 수학·과학에서 지속적으로 겪는 성취도 격차의 주요 원인으로 지목되고 있다.

따라서 본 연구는 단순한 데이터 변환이나 접근성 보조 기술 개발을 넘어,  
 **① 실시간 변환**,  
 **② 의미 기반 분석**,  
 **③ 비선형 구조 제공**,  
 **④ 점자·음성 출력에 최적화된 재조직 알고리즘**  
 을 아우르는 새로운 학습 접근성 모델의 필요성을 제기한다. 이는 시각장애 수험생의 학습권 보장뿐 아니라, 향후 교육 접근성 기술의 방향을 재정의하는 의미 있는 연구적 기여가 될 수 있다.

#### **1.4 연구 목적**

본 연구의 궁극적인 목적은 시각장애 수험생이 수능특강과 같은 핵심 교재를 **비장애 학생과 동일한 시점·동일한 정보 구조로 학습할 수 있도록 하는 새로운 접근성 기반 학습 시스템을 제안하는 것**이다. 이를 위해 본 연구는 기존 점역 방식과 스크린리더 중심의 선형 정보 제공 모델이 지닌 구조적 한계를 극복하고, 원본 PDF의 시각적 구조를 **의미 단위로 재해석하여 점자·음성으로 실시간 제공하는 기술적 프레임워크**를 구축하고자 한다.

첫째, 본 연구는 \*\*PDF → 점자/음성 전처리 자동화(PDF Accessibility Preprocessing Automation)\*\*를 주요 목표로 한다. 수능특강 PDF는 그래프·표·문항·지문 등 다양한 요소가 시각적으로 배치된 복합 자료로 구성되어 있으나, 현재 점역 과정은 이를 단순 텍스트 변환 방식으로 처리하여 구조를 상실하게 만든다. 본 연구는 OCR, 레이아웃 분석, LLM 기반 의미 추출 기법을 결합하여, PDF의 시각적 구획을 자동으로 식별하고 텍스트·그래프·선택지를 **학습 가능 형태로 자동 전처리하는 파이프라인**을 구축한다. 이를 통해 시각장애 수험생은 교재 출간 즉시 접근 가능한 학습 환경을 확보할 수 있다.

둘째, 본 연구는 \*\*그래프·문항 구조의 의미 기반 재구성(Meaning-Based Reorganization)\*\*을 핵심 기여 요소로 제시한다. 그래프의 형태적 정보(증감, 극값, 교점, 기울기)와 문항의 논리적 구조(근거 문장, 선택지 비교 관계, 조건·반박 구조)는 점자·음성 출력으로 단순 치환될 수 없기 때문에, 본 연구는 그래프 분석 모델, 문항-근거 매핑 알고리즘, 선택지 논리구조 분석 모델을 통해 **문제 해결에 실제 필요한 의미 요소를 추출하여 구조화하는 방식**을 연구한다. 이는 시각장애 수험생이 원본 그래프·지문이 제공하지 않던 **“문제 중심 정보”를 더 직관적으로 접근**할 수 있도록 한다.

셋째, 본 연구는 \*\*3셀 점자 기반 저비용 접근성 모델(Low-Cost 3-Cell Braille Model)\*\*을 제안한다. 기존 점자 디스플레이는 고가·고전력·대형 장비가 대부분이며, 개인 수험생이 휴대하고 학습 과정에 지속적으로 활용하기 어렵다. 본 연구는 소형·저전력·저비용의 3셀 점자 디바이스를 기반으로, 방대한 텍스트·그래프 정보를 **의미 청크(braille semantic chunk)** 형태로 압축하여 제공하는 방식을 개발한다. 이를 통해 기존 점자 기술이 해결하지 못한 **고차원 정보의 점자화 문제**를 새로운 인코딩 방식으로 해결하고, 실제 학습 상황에서 활용 가능한 지속적 접근성을 제공한다.

결국, 본 연구는  
 **① 실시간 접근성 확보**,  
 **② 의미 기반 정보 재구성**,  
 **③ 저비용 점자 기술을 사용하는 새로운 학습 모델 제안**  
 이라는 세 가지 축을 중심으로, 시각장애 수험생의 학습권·평등권 증진을 위한 **새로운 형태의 수능 대비 학습 인프라를 구축하는 것**을 목표로 한다.

#### **1.5 연구 질문**

본 연구는 시각장애 수험생의 수능 대비 과정에서 발생하는 구조적 접근성 문제를 해결하기 위해 새로운 접근성 기반 학습 시스템을 제안하고자 하며, 이를 위해 다음의 구체적 연구 질문을 설정한다.

### **RQ1. 시각장애 수험생이 학습 과정에서 겪는 가장 큰 정보 접근성 문제는 무엇인가?**

수능특강 PDF와 점역본에서 발생하는 구조적 손실, 그래프·표·지문의 비선형 정보 접근 어려움, 점자 읽기 속도 및 탐색 한계 등 기존 학습 환경에서 나타나는 근본적 문제를 분석한다. 이를 통해 시스템 설계가 해결해야 하는 핵심 접근성 요구사항을 규명한다.

### **RQ2. PDF 기반 교재를 어떻게 실시간으로 자동 접근성화할 수 있는가?**

수능특강 PDF의 시각적 레이아웃—지문, 문항, 선택지, 그래프, 표—을 OCR·레이아웃 분석·LLM 기법을 활용해 의미 단위로 분해하고, 이를 점자/음성 학습에 적합한 구조로 재조합할 수 있는 전처리 파이프라인의 기술적 가능성을 탐구한다.  
 특히 점역 지연 문제를 해소하기 위해 “원본 PDF 공개 즉시 사용 가능한 자동 접근성 변환”의 실현 가능성을 검토한다.

### **RQ3. 그래프·표·선택지 등 고난도 시각정보를 점자·음성으로 의미 있게 변환하는 방법은 무엇인가?**

좌표(축, 극값, 교점), 데이터 관계, 증감 구간, 선택지 논리구조 등 시각 중심 정보에서 문제 해결에 필요한 의미 요소를 자동으로 추출하여, 점자·음성 기반 비선형 정보 탐색이 가능하도록 재구성할 수 있는 알고리즘적 방법을 탐색한다.  
 이는 기존 점역 방식이 가지는 설명적 한계와 스크린리더의 선형적 정보 처리 한계를 극복하기 위한 핵심 연구 질문이다.

### **RQ4. 점자 디바이스가 단 3셀일 때, 방대한 학습 정보를 어떻게 압축·구조화할 수 있는가?**

고가의 다셀 점자 디스플레이가 아닌, 저비용·소형 3셀 점자 디바이스를 활용하여 방대한 텍스트·그래프 정보를 효율적으로 제공하기 위한 ‘의미 청크(braille semantic chunk)’ 기반 인코딩 방식을 제안할 수 있는지 탐구한다.  
 이 연구 질문은 단순 점자 출력이 아니라, **의미 기반 정보 압축**이라는 새로운 접근성 모델의 가능성을 다룬다.

### **종합적으로, 본 연구는 위의 네 가지 질문을 통해**

* 기존 점역 기술의 구조적 한계  
* 시각장애 수험생의 비선형 정보 접근 요구  
* AI 기반 의미 변환 기술의 실용 가능성  
* 저비용 점자 디바이스 기반 학습 인프라 구축 가능성

을 체계적으로 조사하고, 시각장애인을 위한 새로운 형태의 수능 대비 학습 플랫폼의 기술적·교육적 타당성을 검증하는 데 목적을 둔다.

## **제 2장 선행연구**

#### **2.1 시각장애 학생의 교육 접근성**

시각장애 학생의 학습 접근성은 정보 처리 방식의 구조적 차이로 인해 일반 학습 환경과 근본적으로 다른 제약을 가진다. 본 절에서는 점자 읽기 속도, 교재 제공 시점 문제, 선형 읽기 방식의 한계를 중심으로 기존 연구를 검토한다.

1) 점자 읽기 속도 및 정보 처리 특성

점자는 촉각 기반의 문자 체계로, 시각 기반 읽기보다 구조적으로 느린 정보 처리 속도를 가진다. 여러 연구에서 공통적으로 점자 읽기 속도는 일반 인쇄물 읽기 속도의 **약 30\~50% 수준**으로 보고되고 있으며(Arter & Brambring, 1999; Emerson et al., 2009), 읽기 속도는 평균 **70\~100 wpm(words per minute)** 수준으로 나타난다. 반면, 일반 시각 자료의 평균 읽기 속도는 200\~300 wpm이다.

또한 점자 정보는 한 번에 촉지 가능한 범위가 매우 제한되기 때문에(약 1\~3단어 단위), 시각 정보처럼 전체 문장·문단·페이지 구조를 한눈에 파악할 수 없다. 연구들은 이러한 점자 읽기의 \*\*선형성(linearity)\*\*이 문서의 전반적 구조 파악, 탐색 속도, 특정 문장으로의 빠른 이동 등을 어렵게 만들어 학습 효율에 큰 영향을 준다고 지적한다(Ferrell & Mason, 2010).

특히 수능과 같이 장문 지문과 복잡한 문항 구조가 결합된 시험에서는 점자를 통한 정보처리 한계가 더욱 두드러진다. 이는 시각장애 학생의 응시 시간 연장 제도의 근거이기도 하다.

2) 시험·교재 제공 시점 문제

시각장애 학생의 교육 접근성에서 반복적으로 지적되는 핵심 문제는 **교재 제공 시점의 지연**이다. 현재 국내 점역 시스템은 대부분 수작업 기반으로 운영되고 있으며, 전문 점역사와 검수 인력 부족, 교재 제작 프로세스 지연 등으로 인해 일반 교재가 출간된 이후 **수주에서 수개월의 시간이 지난 뒤**에야 시각장애 학생에게 점역본이 제공된다.

교육부 보고(한국시각장애인연합회, 2020)에서도 교과서·학습자료의 점역본이 대부분 해당 학기의 중반 혹은 후반에 제공되는 사례가 확인되었으며, 특히 수능특강과 같은 시험 대비 교재는 매년 **9\~10월에야 제공되는 경우**가 많아, 일반 학생 대비 **4\~6개월 이상의 학습 시차**가 발생하는 것으로 보고되었다.

CHsung(2022)의 연구에서도 “점자 교과서는 매 학기 적시에 제공되지 않아 시각장애 학생의 학습권을 심각하게 침해하고 있다”고 지적한다. 이러한 시간적 접근성 격차는 단순 자료 제공 문제를 넘어, 진학 및 성취도 평가에서의 근본적 불평등을 초래한다.

3) 선형 읽기 방식과 정보 구조 상실

시각장애 학생이 사용하는 스크린리더(VoiceOver, NVDA, JAWS 등)는 문서의 시각적 구획을 해석하지 못하고, 텍스트를 **위→아래 순차적으로 읽는 선형적 처리 방식**을 따른다. 이 때문에 문서의 *비선형적 구조*—문단 간 논리 관계, 삽입 그래프, 병렬 선택지, 표의 행·열 구조—가 그대로 보존되지 않는다.

선행연구에 따르면 스크린리더는 지문-문항-해설이 혼재한 문서를 구조적으로 해석하지 못하여, 장문 지문을 단일 텍스트로 변환하거나 그래프·표를 단순 설명 텍스트로 대체하는 경향이 있다(Bigham et al., 2010). 이 과정에서 원본 문서의 의미적 관계(예: “이 그래프는 문단 3의 설명과 대응”)가 손실되어, 시각장애 학습자는 문서 전체 구조를 이해하기 위해 **불필요하게 긴 탐색과 반복청취**를 수행해야 한다.

특히 수능 자료는

* 문단 구조,

* 근거 문장 위치,

* 선택지 간 논리 비교,

* 그래프의 증감·교점·좌표 정보

등 비선형적 구조가 문제 해결의 핵심인데, 기존 접근성 기술은 이 구조를 제공하지 못하므로 학습 효율이 크게 떨어진다.

이러한 구조 손실 문제는 점자 교재에서도 동일하게 나타난다. 그래프는 점묘 방식으로 간략화되거나 텍스트 해설로 대체되며, 표는 단순 나열 형태로 재구조화되기 때문에 정보량과 정밀도가 원본 대비 크게 감소한다(Leão et al., 2018).

### **요약하면, 선행연구는 다음을 일관되게 지적한다.**

* 점자 읽기 속도는 시각 읽기보다 현저히 느리다.  
* 점역본 제공 지연은 학습 시작 시점을 구조적으로 뒤로 미룬다.  
* 스크린리더/점역본은 비선형 구조를 선형 텍스트로 변환하여 정보 구조가 붕괴된다.  
* 그래프·표·논리 구조 등 시각 중심 정보는 대체 텍스트만으로 충분히 전달되지 않는다.

이러한 연구 결과는 본 연구가 제안하는 **PDF 구조 분석 → 의미 기반 재구성 → 점자·음성 제공** 시스템의 필요성을 직접적으로 뒷받침한다.

#### **2.2 교재 점역 및 대체교과서 연구**

시각장애 학생 교육에서 가장 지속적으로 제기되는 문제 중 하나는 **교재 점역 속도와 품질의 한계**이다. 본 절에서는 점자·전자교과서 제공 지연 문제와 점역 과정에서 반복적으로 나타나는 표·그래프 오류 연구를 중심으로 기존 문헌을 검토한다.

1) 점자·전자교과서 제공 지연 문제

국내외 시각장애 교육 연구는 시각장애 학생이 \*\*교과서와 학습자료를 ‘제때 제공받지 못한다’\*\*는 점을 공통된 구조적 문제로 제시한다. 점역본 제작은 대부분 인력 중심의 수작업에 의존하고 있으며, 편집·검수·교열 단계가 추가되기 때문에 속도가 매우 느리다.

국내 연구 보고서(한국시각장애인연합회, 2020)에 따르면,

* 일반 교과서가 학기 시작 전 제공되는 반면

* 점자 교과서는 **학기 중반\~후반**에 제공되는 사례가 빈번하며

* 특히 방대한 분량의 참고서·EBS 수능특강 교재는 **매년 9–10월에야 완성**되는 경우가 많다.

이는 비장애 학생이 3월부터 시작하는 수능 대비 학습을 시각장애 학생은 **가을 이후에야 시작할 수 있게 되는 심각한 시차 문제**로 이어진다.  
 연구에 따르면 이러한 시차는 단순한 ‘시간적 불편’이 아니라 실제 학업 성취도와 대학 입시에 영향을 미치는 **구조적 교육 불평등 요인**으로 기능한다(CHsung, 2022).

또한 전자교과서(e-Textbook) 역시 제공 시점이 늦어지거나, 원본과 동일한 구조를 갖추지 못한 채 제공되는 경우가 많아 접근성을 근본적으로 개선하는 데 한계를 드러낸다(Lee & Lee, 2019).

요약하면, 기존 점역·전자교과서 체계는

* 제공 시점이 늦고

* 원본 구조가 충분히 보존되지 않으며

* 변화하는 수능·교육과정에 실시간 대응이 불가능  
   하다는 점에서 시각장애 학생의 학습권을 보장하기에 충분하지 않다.

2) 표·그래프·도형 점역 오류 및 한계 연구

두 번째 주요 문제는 **표, 그래프, 도형 등의 시각자료를 점자로 정확히 변환하는 것이 기술적으로 매우 어렵다는 점**이다.  
 이와 관련한 연구들은 점역 과정에서 반복적으로 나타나는 오류 유형을 다음과 같이 제시한다.

### **① 정보 축약 및 누락 문제**

표와 그래프는 본래 비교·관계·값의 변화가 중요하지만, 대부분의 점자 교재에서는

* 열/행 구분이 모호해지거나

* 데이터가 단순 나열로 표현되거나

* 그래프 좌표·증감 패턴이 설명형 문장으로 축약되는 등  
   **구조적·정량적 정보가 크게 손실**된다.

실제로 미국 시각장애교육연구소(NFB, 2018)는 그래프 점역에서 가장 문제가 되는 부분으로

* 기울기 정보의 손실

* 좌표 관계의 변형

* 데이터 간 비교 불가  
   를 반복적으로 지적하였다.

### **② 점자 그래픽(촉각도형) 제작 비용과 물리적 한계**

촉각 그래프는 제작 비용이 높고 크기가 크기 때문에

* 대량 생산이 불가능하고  
* 교재 전체 그래프를 모두 점묘/부조 형태로 만드는 것은 현실적으로 불가하다.

결과적으로 시각장애 학생은 교재에서 등장하는 수많은 그래프·표·도형 중  
 일부만 촉각 자료로 제공받고, 나머지는 텍스트 해설로 대체하게 된다.

### **③ 수학·과학 기반 그래프 점역의 낮은 정확도**

수학 문제에서 사용되는

* 극값

* 교점

* 기울기

* 근의 형태

* 증가/감소 구간  
   등은 텍스트로 변환될 때 **정확도·일관성·문장 길이** 문제로 인해 의미 전달력이 떨어진다.

Leão et al.(2018)의 연구에 따르면 점자 그래프는  
 사용자가 “어디가 중요한 정보인지”를 이해하기 어렵고,  
 중요하지 않은 부분이 과도하게 설명되는 경향도 있어  
 **‘문제 해결 중심의 정보 추출’이 제대로 이루어지지 않는다**고 보고되었다.

### **④ 문항 구조 자체의 비선형성 손실**

표·그래프뿐 아니라  
 지문-문항-선택지의 공간적 배치도 점역 과정에서 모두 선형화되므로

* 특정 선택지가 지문의 어느 문장을 근거로 하는지

* 문항의 조건/반박 구조

* 보기들의 논리적 관계  
   를 알기 위해 사용자는 처음부터 끝까지 전체 텍스트를 순차적으로 파악해야 한다.

이 문제는 기존 점역본과 스크린리더가 공통으로 가지는 구조적 한계로,  
 최근 연구들도 “문항 구조를 보존한 점역 모델의 필요성”을 강조하고 있다(Seo & Jeong, 2021).

#### **2.3 접근성 기술 연구**

시각장애인의 학습 자료 접근성을 위해 다양한 기술이 개발되어 왔으나, 기존 접근성 기술은 **문서 구조 해석의 부재**, **시각적 요소의 의미 추출 실패**, **선형 정보 처리 방식**이라는 공통된 한계를 가진다. 본 절에서는 스크린리더 기술, OCR 기반 문서 인식 기술, 그래프·표·도형 점자화 기술을 중심으로 현재 연구 동향과 한계를 검토한다.

1) 스크린리더(Screen Reader) 기술의 구조적 한계

스크린리더(NVDA, VoiceOver, JAWS 등)는 시각장애인의 디지털 정보 접근에 가장 널리 사용되는 도구이지만, 기술적 구조 특성상 **문서의 시각적 레이아웃을 의미 단위로 해석하지 못한다**는 치명적 한계가 존재한다.

### **① 선형 읽기 방식으로 인한 구조 붕괴**

스크린리더는 HTML·PDF·문서 파일의 내용을 \*\*위→아래로 순차적으로 직렬 처리(linear processing)\*\*한다.  
 이로 인해 다음과 같은 정보들이 보존되지 않는다.

* 지문과 문항의 위치 관계

* 선택지 간 병렬 구조

* 표의 행·열 관계

* 그래프의 축 구조 및 시각적 맥락

* 강조 정보, 문단 간 논리 연결

Bigham et al.(2010)은 스크린리더가 “문서의 시각적 맥락을 잃으면서 비선형 구조를 모두 파괴한다”고 지적했다.

### **② 복잡 문서 인식의 낮은 정확도**

스크린리더가 PDF 내부의 구조적 메타데이터를 정확히 인식하지 못할 경우,

* 문단 순서가 뒤섞이거나

* 그래프 캡션이 본문에 삽입되거나

* 선택지가 지문 중간에 끼어드는 등  
   문서 파싱 오류가 발생한다.

수능특강·EBS 교재처럼 **복합적 레이아웃을 가진 시험 자료**에서는 이러한 오류가 더욱 심해진다.

### **③ 시각 중심 정보 제공 불가**

스크린리더는 이미지에 대해 “대체텍스트”만 읽을 수 있으며,  
 그래프·표·도형의 의미 구조를 분석하는 기능은 없다.

결과적으로 시각장애 수험생은

* 그래프 해석

* 표 비교

* 도형 정보 파악  
   을 위해 외부 설명에 전적으로 의존해야 하며, 이는 문제 해결 효율을 크게 저해한다.

## **2\) OCR(문자인식) 기반 문서 접근 기술의 한계**

OCR 기술의 발전은 텍스트 인식률을 크게 향상시켰지만, 교육 접근성 연구에서는 다음과 같은 구조적 한계가 반복적으로 보고되고 있다.

### **① 텍스트 인식에만 최적화된 기술**

OCR 모델은 기본적으로 문자를 인식하는 기술로,

* 그래프의 축

* 좌표

* 기호

* 수식 구조

* 표의 행·열 관계  
   를 **텍스트로 치환할 때 원본 의미가 소실**된다.

Tesseract, Google Vision 등 최신 OCR 엔진도  
 표의 구조적 관계나 그래프의 시각적 패턴을 자동으로 재구성하지 못한다.

### **② PDF 레이아웃 복원 불가**

PDF는 그래픽 요소·텍스트·레이어가 혼합된 비정형 구조이기 때문에,  
 OCR을 적용해 텍스트를 추출해도 원본과 동일한 **읽기 순서나 의미 구조**를 복원할 수 없다.

이는 EBS 수능특강처럼

* 지문,

* 소문(小文),

* 각주,

* 그래프,

* 사진,

* 선택지 박스  
   가 한 페이지에 혼재하는 자료에서는 더욱 심각한 문제를 야기한다.

### **③ 그래프·도형 인식 정확도의 근본적 한계**

OCR은 픽셀→문자 정보로 전환하는 기술이기 때문에  
 그래프의 형태적 특징(증감, 기울기, 좌표 관계)을 의미 기반으로 추출할 수 없다.

따라서 수학·과학 문제에서는  
 **그래프 전체가 ‘이미지 블록’으로만 판정되며,**  
 유의미한 정보 추출이 불가능하다.

## **3\) 그래프·표·도형 점자화 기술의 한계**

그래프 접근성을 높이기 위한 다양한 점자화 기술(촉각 그래프, 점묘 그래픽, 음성그래프)이 연구되었지만, 교육 현장에서 실질적으로 적용하기에는 명확한 한계가 있다.

### **① 촉각 그래프의 비용·크기·생산성 문제**

촉각 그래프는

* 제작 단가가 높고

* 교재 전체를 제작하기 어렵고

* 휴대성이 떨어지고

* 업데이트가 불가능

하여 **대규모 학습자료(수능특강 등)에 적용 불가능**하다.

### **② 정보 과부하 및 의미 전달의 비효율성**

연구에 따르면, 촉각 그래프는

* 불필요한 디테일이 과도하게 표현되거나

* 핵심 요소가 추출되지 않아  
   사용자가 “어디를 만져야 하는지” 파악하기 어렵다는 문제가 있다(Leão et al., 2018).

즉, 촉각 정밀도는 높지만  
 **“교육적 의미 구조”가 제공되지 않는다.**

### **③ 점자 그래픽의 표현 한계**

점자 그래픽은 기호·좌표·곡선 표현에 기술적 한계가 있어

* 기울기

* 함수 형태

* 미세한 변화  
   를 점으로 표현할 수 없다.

결과적으로 그래프·표 기반 수능 문제의 70% 이상이  
 **점자화 불가능하거나 의미 손실이 매우 큰 문제**로 분류된다.

## **선행연구의 핵심 결론**

기존 접근성 기술은  
 ✔ 텍스트는 읽을 수 있으나 구조는 잃는다  
 ✔ 시각 중심 요소(그래프·표)는 사실상 “대체 텍스트화”에 머문다  
 ✔ 점자·스크린리더 기반의 선형 정보 제공은 학습 효율을 심각하게 저해한다  
 ✔ 시험 대비 교재처럼 복잡한 문서를 처리하는 데 근본적 제한이 있다

즉, **“문서 구조 전체를 의미 단위로 재구성하는 접근성 기술”은 아직 존재하지 않는다.**

이 공백이 바로 본 연구가 해결하려는 지점이다.

#### **2.4 그래프 · 표 의미 분석**

그래프와 표는 수학·과학·언어영역 평가에서 핵심적인 시각 정보로 기능하며, 시각장애 학생의 학습 접근성에서 가장 어려운 요소로 반복적으로 지적되어 왔다. 최근 AI·컴퓨터비전(CV) 기술을 활용하여 그래프의 형태적 특징을 자동으로 추출하거나, 음성·기호 기반으로 의미를 표현하려는 연구들이 진행되고 있으나, 아직까지 교육 현장에서 실질적으로 활용 가능한 수준의 **의미 기반 구조화 모델**은 확립되지 않았다. 본 절에서는 CV 기반 그래프 특징 추출 연구와 그래프 의미 표현(sonification, symbolic encoding) 연구를 중심으로 관련 연구 동향과 한계를 살펴본다.

1) CV 기반 그래프 특징 추출 연구 (Computer Vision–Based Graph Interpretation)

### **① 그래프의 구조적 요소 자동 추출 연구**

여러 연구에서 CV 모델을 통해 그래프의 다음과 같은 요소를 자동 검출하는 기법이 제안되었다.

* **좌표축 검출(axis detection)**

* **데이터 곡선/선분 segmentation**

* **최대·최소값 극점(peak detection)**

* **교점·절편(intersection) 검출**

* **증가/감소 구간(derivative-like patterns) 분석**

예를 들어, Siegel et al.(2020)은 딥러닝 기반 이미지 분석으로 2D 그래프에서 곡선을 추출하고 형태학적 특징(기울기 변화·곡률 등)을 분석하는 모델을 개발하였다.  
 Li & Tan(2019)은 그래프에서 데이터 포인트와 함수 경로를 분리하여 핵심 특징만 추출하는 알고리즘을 제안하였다.

### **② 복잡 그래프 해석의 정확도 문제**

하지만 기존 연구들은 다음과 같은 한계를 가진다.

* PDF 기반 시험자료처럼 **저해상도·복합 그래프**에서는 인식률이 하락

* 데이터형 그래프는 처리 가능하지만, **수능형 함수 그래프(변곡점·도함수 기반 형태)는 인식 난이도가 매우 높음**

* 좌표 정보가 이미지에 내재되지 않아 **정확한 수치 기반 판단이 어려움**

즉, 그래프의 형태 자체를 인식하는 기술은 존재하지만,  
 “문제 해결 중심의 핵심 정보(극값·교점·증감 구간)”를  
 점자·음성에 적합한 **의미 단위로 변환하는 기술**은 아직 확립되어 있지 않다.

## **2\) 그래프 의미 표현 연구 (Sonification, Symbolic Encoding)**

그래프의 의미를 시각장애인에게 제공하기 위한 또 다른 연구 흐름은 \*\*음성 기반 표현(sonification)\*\*과 \*\*기호 기반 압축(symbolic encoding)\*\*이다.

### **① Sonification(음향화) 기반 그래프 표현 연구**

Sonification 연구는 데이터 값을 소리의 높낮이·속도·리듬 등으로 변환하는 방식으로,  
 시각 데이터를 청각적 패턴으로 전달하는 기술이다.

예:

* 값이 증가하면 pitch 상승

* 극값에서는 tone change

* 교점에서 beep 발생

* 기울기 변화는 속도 변화로 표현

Zhao et al.(2005)은 그래프 선형 데이터를 시간 기반 사운드로 변환하는 기법을 제안하였고,  
 구글의 AudioGraphs 프로젝트 또한 similar sonification 방식으로 그래프를 전달한다.

하지만 Sonification은 다음 한계를 가진다.

* **청각 피로도가 빠르게 증가**

* 그래프의 전체 구조를 “한 번에” 이해하기 어려움

* 수능 문제처럼 복잡한 조건/함수의 의미적 핵심을 빠르게 파악하기 어려움

즉, 그래프의 “전체 패턴”을 느끼는 데는 유용하지만,  
 문제 해결을 위해 필요한 “의미 구조(증감·극점·교점 등)”를 직접적으로 전달하기 어렵다.

### **② Symbolic Encoding(기호 기반 의미 압축) 연구**

그래프를 기호적 단위로 표현하는 시도도 존재한다.

* 그래프를 ‘증가 ↑’, ‘감소 ↓’, ‘극대 ●’, ‘극소 ○’, ‘교점 ×’ 같은 상징으로 요약

* 선형 그래프를 계층적 구조로 재구성

* 의미 단위를 나열하는 방식으로 점자·텍스트로 변환

이 방식은 점자 기반 환경에서 그래프를 표현할 수 있는 가능성을 제시하지만,  
 기존 연구들은 대부분

* 단순 그래프(일차·이차 함수) 수준에서만 실험되었고

* 문제 해결 중심의 의미 구조(조건부 변화, 문항 중심 요소 선택)를 반영하지 못하며

* 자동화 파이프라인 없이 수동 상징 변환에 의존하는 한계  
   를 가진다.

즉, symbolic encoding은 원리를 제안했지만, 실제 학습자료에 적용할 수준의 자동화·고도화는 이루어지지 않은 상태다.

## **3\) 선행연구의 공백과 본 연구의 기여 방향**

기존 그래프·표 의미 분석 연구는  
 **“그래프를 인식하는 기술”** 또는  
 \*\*“그래프를 들려주는 기술”\*\*은 제안했지만,  
 다음과 같은 핵심 문제는 여전히 해결하지 못했다.

### **현재 연구의 빈틈**

✔ 시험 PDF에서 그래프를 자동 분리해내는 기술  
 ✔ 그래프의 의미 요소를 “문제 해결 관점”에서 추출하는 기술  
 ✔ 점자·음성 기반으로 제공하기 위한 **의미 압축 모델**  
 ✔ 선형 텍스트로 전환하지 않고 **비선형 구조를 유지하는 모델**  
 ✔ 3셀 점자 디바이스에 최적화된 요약/청크 제공 방식

즉, 기존 연구는 그래프의 “형태 인식” 또는 “대체 표현”에 머물렀고,  
 시각장애 수험생의 실질적인 문제 해결을 위한  
 **“의미 기반 재구성” 연구는 거의 전무한 상태**이다.

## **본 연구가 채우는 연구 공백**

본 연구는 기존 기술이 해결하지 못한

* 그래프 이미지 → 의미 요소 추출

* 문항 맥락 기반 정보 정렬

* 점자·음성에 적합한 의미 청크 재조합

* 3셀 점자 디바이스 기반 표현 모델  
   을 모두 결합한 **새로운 접근성 변환 구조**를 제안한다.

즉, “그래프를 읽는 기술”이 아니라  
 **그래프를 ‘이해하도록 만드는’ 기술**을 설계하는 것이 본 연구의 차별점이다.

#### **2.5  AI 기반 교육 지원 연구**

AI 기술, 특히 대규모 언어모델(LLM)을 활용한 교육 지원 연구는 최근 급격히 발전하고 있으며, 요약·문항 분석·개인화 학습 등 다양한 영역에서 학습 효율 향상을 위한 시도가 이루어지고 있다. 본 절에서는 LLM 기반 요약 연구, 문항 이해·오답 분석 연구, 개인화 학습 알고리즘을 중심으로 선행 연구 동향을 검토한다.

## **1\) LLM 기반 요약(Summarization) 연구**

대규모 언어모델(GPT, LLaMA, PaLM 등)의 등장 이후, 텍스트 요약(summarization)은 가장 활발히 연구된 AI 학습 지원 기술 중 하나이다.

### **① 단순 요약(Extractive/Abstractive Summarization)**

* GPT-4, T5, BART 기반 연구에서는 장문 텍스트의 핵심 문장을 추출하거나

* 의미 단위로 재구성하는 능력이 기존 통계 기반 summarizer보다 압도적으로 우수한 것으로 보고되었다(Liu & Lapata, 2019).

그러나 기존 요약 연구는 대부분

* 뉴스 기사

* 문학 작품

* 비정형 텍스트  
   에 적용되었으며, **교육용 지문·수능 수준의 구조적 텍스트에 특화된 연구는 부족**하다.

### **② 교육 맥락에서의 요약 연구의 한계**

교육 자료는 일반 문서와 달리

* 중심 문장

* 논증 구조

* 문항의 근거 문장

* 문단 간 논리 흐름  
   등 구조적 요소의 보존이 필수적이다.

하지만 대부분의 LLM 요약 모델은  
 “전체 의미 요약”에는 능하지만,  
 “문항 해결에 필요한 핵심 요소만 추출하는 구조적 요약”에는 특화되지 않았다.

이 한계는

시각장애 수험생에게 필요한 ‘문항 기반 요약’과는 본질적으로 다르다.

본 연구는 바로 이 공백을 해결하는 새로운 요약 구조를 제안한다.

## **2\) 문항 이해 및 오답 분석 연구**

AI 기반 교육 연구에서 또 다른 핵심 분야는  
 **문항을 이해하고, 학생이 왜 오답을 선택했는지 분석하는 연구**이다.

### **① 문항 자동 분류·이해 연구**

최근 LLM(Ahn et al., 2023)은 문항을

* 유형(추론, 어휘, 지문 연결 등)

* 난이도

* 필요한 사고 과정  
   등으로 자동 태깅하는 데 높은 정확도를 보였다.

이는 수능과 같은 고난도 시험에서도 문항의 ‘지식 구조’를 해석하는 데 적용될 수 있다는 가능성을 보여준다.

### **② 오답 패턴 분석 연구**

Deep Knowledge Tracing(DKT), transformer 기반 Student Modeling 연구들은  
 학생의 반응 패턴을 기반으로

* 어떤 개념이 취약한지

* 어떤 유형을 반복적으로 틀리는지

* 어떤 지문 구조에서 이해도가 낮은지  
   를 자동 예측할 수 있음을 보여주었다.

특히 Google Research의 “Eedi Student Modeling”(2021)은  
 오답 선택지가 학생의 사고 오류를 반영한다는 점을 정량적으로 증명하였다.

### **하지만 시각장애 학생 연구는 거의 없음**

기존 오답 분석 연구는 “비장애 학생의 온라인 학습 데이터” 중심으로 이루어졌으며,  
 시각장애 수험생의

* 점자 기반 입력

* 선형 탐색 패턴

* 재청취 기록

* 탐색 경로  
   같은 *접근성 특화 행동 데이터*를 분석한 연구는 거의 없다.

즉, ‘시각장애 학습 데이터를 기반으로 한 AI 학습 지원 연구’는 아직 미개척 분야다.  
 이 공백을 본 연구가 새롭게 제시한다.

## **3\) 개인화 학습 알고리즘(Personalized Learning Algorithms)**

AI 기반 교육에서 가장 중요한 주제 중 하나는 \*\*개인화(personalization)\*\*이다.

### **① 기존 개인화 알고리즘**

* Bayesian Knowledge Tracing(BKT)

* Deep Knowledge Tracing(DKT)

* Graph Neural Network 기반 학습자 모델(GNNT)

* Multi-armed bandit 기반 난이도 조절  
   등은 학생의 최근 학습 성과를 기반으로 다음 문제의 적절한 난이도를 추천한다.

이 알고리즘들은

* 학습 효율 향상

* 연습량 최적화

* 지식 결손 최소화  
   에서 효과가 있음이 이미 입증되었다.

### **② LLM 기반 개인화 연구의 부상**

GPT-4 이후에는

* 학습 스타일 분석

* 개념적 약점 설명

* 맞춤형 힌트 제공

* 복습 큐 자동 생성  
   과 같은 **고급 개인화 기능**도 가능해졌다.

예:  
 Khan Academy의 Khanmigo  
 → 학생 질문 패턴 분석 → 맞춤 피드백 제공  
 NYU에서 진행 중인 “LLM Tutor 연구”  
 → 학생의 사고 과정 기반 힌트 제공

### **③ 시각장애 학생의 개인화 연구는 거의 없음**

그러나 기존 개인화 연구는 모두  
 \*\*“시각 정보 기반 학습을 전제로 한 사용자 모델”\*\*이라는 전제가 있다.

즉,

* 점자 입력

* 음성 기반 탐색

* 선형 정보 처리

* 점자 디바이스 사용 패턴  
   에 기반한 개인화 알고리즘 연구는 *사실상 존재하지 않는다*.

시각장애 학습자는 학습 행동 자체가 비장애 학생과 다르기 때문에,  
 기존 개인화 모델을 그대로 적용할 수 없다.

본 연구는

* 점자 출력 패턴

* 재청취 횟수

* 지문 탐색 경로

* 선택지 비교 시간  
   같은 새로운 행동 지표를 활용하여 시각장애 수험생에 특화된 **개인화 학습 모델의 가능성**을 제안한다.

## **선행연구의 결론**

기존 AI 기반 교육 연구는  
 ✔ 요약  
 ✔ 문항 분석  
 ✔ 오답 패턴 모델링  
 ✔ 개인화 알고리즘  
 에서는 큰 발전을 이루었지만,

다음 문제는 여전히 해결되지 않았다:

* 수능 수준의 복잡한 지문·문항 구조를 **문항 중심**으로 요약하는 연구

* 시각장애 학습자 데이터 기반 AI 연구

* 점자·음성 기반 비선형 학습 모델

* 그래프/표 의미 재구성과 개인화 모델의 결합

* 3셀 점자 디바이스에 최적화된 정보 제공 방식

즉, 기존 연구는 "비장애 학생 중심 AI 학습 지원"에 머물러 있으며,  
 시각장애 수험생의 **구조적 학습 문제를 해결하는 AI 모델**은 사실상 부재하다.

이 점이 바로 본 연구의 핵심 기여로 이어진다.

#### **2.6 선행연구의 한계**

앞선 연구들을 종합해보면, 시각장애 학생의 학습 접근성을 개선하기 위한 다양한 기술적·교육학적 시도들이 이루어져 왔으나, 이러한 연구들은 수능 대비와 같은 실제 학습 상황에서 발생하는 핵심 문제를 해결하기에는 구조적 한계를 가진다. 특히 **실시간 접근성 변환 기술의 부재**, **저비용 점자 디바이스 기반 연구의 부족**, **수능특강/EBS 교재 구조에 대한 특화 연구의 부재**라는 세 가지 한계는 시각장애 수험생의 학습 격차를 해소하는 데 결정적인 장애 요소로 남아 있다.

## **1\) 실시간 PDF 접근성 변환 연구의 부재**

기존 점자 교과서·전자책·스크린리더 연구는 대부분 이미 준비된 텍스트·점자 파일을 활용하거나, 단순 문서 구조 파싱에 기반한 방식으로 이루어져 왔다. 따라서 원본 교재가 PDF로 배포되는 즉시 접근성을 확보하는 \*\*실시간 변환 기술(real-time accessibility transformation)\*\*은 거의 연구되지 않았다.

특히 다음과 같은 중요한 공백이 존재한다.

* PDF의 복합적 시각 구조(그래프·표·문항 박스·캡션)를 **의미 기반으로 분해**하는 연구 없음

* OCR 기반 인식 후, 지문–문항–선택지를 **수능형 구조에 맞게 재배열**하는 알고리즘 부재

* 선택지 구조, 문항 유형, 근거 문장 위치 등 **문항 해결에 필요한 정보 중심**으로 재구성하는 연구 없음

* 점역 지연 문제를 해결하기 위한 **자동 점역/접근성 생성 파이프라인 자체가 존재하지 않음**

즉, 기존 기술은 “읽어주는 기술” 또는 “문서를 변환하는 기술”에 머물러 있을 뿐,  
 **수능 교재를 실시간으로 학습 가능한 형태로 재조직하는 기술**은 사실상 부재하다.

## **2\) 저비용 점자 디바이스 기반 연구의 부족**

기존 점자 디스플레이 연구는 대부분

* 32셀, 40셀, 80셀  
   과 같은 **고가의 대형 점자 디스플레이**를 전제로 진행되었다.

그러나 이러한 장비는

* 가격이 수백만 원\~천만 원대에 이르고

* 휴대성이 낮고

* 학교·가정에서 보급률이 매우 낮으며

* 유지보수 비용이 크기 때문에

**개인 학습용으로 활용되기 어렵다.**

현재까지 발표된 점자 기반 학습 연구는  
 대부분 “다셀 점자 디스플레이”를 전제로 하고 있어,  
 소형·경량·저비용 디바이스(예: 1\~3셀) 기반의  
 **접근성 알고리즘 자체가 연구되지 않았다.**

특히 다음 연구 공백이 존재한다.

* 3셀 점자로 그래프·문단 구조·선택지 논리를 전달하는 **의미 압축 모델 부재**

* 저비용 점자 디바이스를 전제로 한 **학습 UX/UI 연구 부족**

* 점자 디바이스 \+ 음성 \+ AI 분석을 결합한 **혼합 접근성 모델 연구 없음**

즉, 저비용 점자 기반 접근성 연구는 현재 거의 미개척 영역이며, 이는 본 연구가 해결하는 핵심 공백이다.

## **3\) 수능특강/EBS 교재에 특화된 연구의 부재**

현재까지 접근성 연구는 대부분

* 웹 접근성(ARIA, HTML 구조)

* 일반 문서 접근성

* 촉각 그래프 제작

* 교과서 점역

* 수학적 그래프 음성화

와 같은 범용 문제를 다루어 왔다.

그러나 시각장애 학생이 실제 입시에서 마주하는 핵심 교재인 **수능특강·수능완성·EBS 연계 교재**는 고유한 구조적 특성을 가진다.

### **수능특강만이 가진 특수 구조**

* 지문 옆에 그래프/표가 배치된 복합 레이아웃

* 문항과 선택지가 페이지 내에서 비선형적으로 배치

* 작은 밑줄·색 강조·번호 박스·중요도 표시 등 시각적 마킹 사용

* 국·영·수 과목별로 서로 다른 시각적 표현 방식

* 지문–문항–해설 간 참조 관계

하지만 선행 연구에서는  
 이러한 수능형 문서 구조를 분석하거나,  
 점자·음성·AI 기반 접근성을 결합하여 처리한 연구가 없다.

다시 말해, 지금까지의 연구 중  
 **수능특강 PDF → 의미 기반 점자·음성 구조 재조직**  
 을 다룬 연구는 단 하나도 없다.

## **종합적으로 볼 때, 기존 연구는 다음 공백을 남긴다**

### **✔ PDF 기반 시험자료의 실시간 접근성 변환 ×**

### **✔ 의미 기반 그래프·표·문항 재구성 ×**

### **✔ 저비용·소형 점자 디바이스 기반 학습 모델 ×**

### **✔ 수능 특화 구조 분석 ×**

### **✔ 국·영·수 통합 접근성 모델 ×**

### **✔ 시각장애 학생의 탐색 패턴을 반영한 개인화 모델 ×**

즉, 기존 연구는 시각장애 수험생의 실제 학습 상황을 해결하기에 **근본적으로 부족한 한계를 가진다.**

이 공백을 해소하는 것이 바로 본 연구가 제안하는  
 \*\*“AI 기반 실시간 PDF 접근성 변환 및 3셀 점자·음성 비선형 학습 시스템”\*\*이다.

## **제 3장 문제 분석**

#### **3.1 시각장애 수험생의 Pain Point**

시각장애 수험생의 수능 대비 과정은 비장애 수험생과 현저하게 다른 정보 환경에서 이루어진다. 특히 점자·음성 기반의 선형 정보 처리 방식과 교재 접근 시점의 지연은 학습 효율과 시험 적응에 심각한 제약을 초래한다. 본 절에서는 시각장애 수험생이 실제 수능 학습 및 응시 과정에서 경험하는 주요 Pain Point를 분석한다.

## **(1) 시험시간·정보 처리 속도 격차**

시각장애 수험생은 점자 또는 음성 기반으로 정보를 선형적으로 처리하기 때문에,  
 문서 전체 구조를 한눈에 파악할 수 없는 구조적 한계를 가진다.  
 점자 읽기 속도는 평균 70–100 wpm으로, 일반 시각 읽기(200–300 wpm)에 비해 현저히 느리다.

이로 인해 동일 문제를 해결하는 데 필요한 시간이 길어지며,  
 **수능 전체 응시 시간이 12시간 이상**으로 늘어나는 등  
 비장애 수험생 대비 **과도한 시간·인지 부담**이 발생한다.

## **(2) 교재 점역 지연으로 인한 학습 시점 격차**

수능특강·EBS 연계 교재는 일반 수험생에게는 3월에 제공되지만,  
 점자·텍스트 점역본은 대부분 **9–10월**에 제공된다.  
 즉, 시각장애 수험생은 일반 수험생보다 **4–6개월 늦게 학습을 시작하는 구조적 불이익**을 겪는다.

이 지연은 단순 교재 제공 문제가 아니라,  
 수험생의 전체 학습 계획·문제 노출 빈도·반복 연습량에 직접적인 손실을 초래한다.

## **(3) 지문 구조·논리 흐름 파악의 어려움**

스크린리더는 문서를 선형적으로 읽기 때문에,  
 지문 전체 구조—문단의 기능, 중심 문장, 논리 흐름, 핵심 근거—를  
 비장애 수험생처럼 시각적으로 “한눈에” 파악하기 어렵다.

그 결과,

* 문항의 근거 문장 위치를 빠르게 찾지 못하고

* 지문 내 정보 간 관계(원인-결과, 조건-반박 등)가 붕괴되며

* 탐색을 위해 불필요한 재청취가 반복되는 문제가 발생한다.

이는 실제 수능 국어·영어 지문의 비선형적 구조를 처리하는 데 결정적 불리함으로 작용한다.

## **(4) 그래프·표·도형 접근 불가능**

수학 및 국어·영어 지문 내 시각자료는  
 점역 과정에서 대부분 “설명형 텍스트”로 변환되거나 누락되기 때문에,

* 함수의 증가/감소

* 극대·극소

* 교점

* 데이터 비교

* 도형의 관계

와 같이 문제 해결에 핵심적인 요소들이 **의미 기반으로 전달되지 않는다.**

기존 촉각 그래프는 제작 비용·크기·수량의 한계로 전 범위 제공이 불가능하며,  
 스크린리더는 그래프 이미지를 단순 대체텍스트로만 처리하기 때문에  
 본질적으로 그래프·표 기반 문제를 해결하기 어렵다.

## **(5) 선택지 비교의 구조적 어려움**

수능 문항에서 선택지는 병렬적으로 놓여 있어  
 비장애 수험생은 시각적으로 빠르게 비교·대조할 수 있다.

그러나 시각장애 수험생은 이를 순차적으로 듣기 때문에:

* 선택지 간 논리적 차이 파악

* 조건·반박 구조 비교

* 유사한 선택지의 미세한 차이 분석

이 매우 어렵다.  
 이 문제는 특히 수능 국어/영어 독해 문제에서 정답률에 큰 영향을 준다.

## **(6) 약점 관리 및 복습 체계 부재**

시각장애 수험생은

* 점자 학습 기록 자동 추적

* 오답 패턴 분석

* 힌트 기반 복습 큐 생성  
   등의 체계적 학습 피드백을 제공받기 어렵다.

기존 점자·음성 기반 학습 환경은  
 “지금 무엇을 틀렸는지, 어떤 유형이 약한지, 무엇을 다시 학습해야 하는지”를  
 시각적으로 구조화해 보여줄 수 없기 때문에,

* 학습 진단

* 누적 복습

* 개인화된 전략 수립

이 불가능하거나 크게 제한된다.

이로 인해 학습 효율이 떨어지고,  
 비장애 수험생라면 시각적으로 즉시 확인할 수 있는  
 “학습 지도(map of learning)” 자체를 구성하기 어렵다.

## **결론적으로, 주요 Pain Point는 6가지로 요약된다**

### **✔ 정보 처리 속도·시험시간의 구조적 격차**

### **✔ 교재 점역 지연으로 인한 학습 시점 격차**

### **✔ 지문 구조·논리 흐름 탐색의 어려움**

### **✔ 그래프·표·도형 접근 불가능**

### **✔ 선택지 비교 불가로 인한 사고 과정 제한**

### **✔ 약점 분석·복습 시스템 부재**

이 Pain Point들은 기술적으로 서로 연결되어 있으며,  
 기존 점역·스크린리더·OCR 기반 접근성 방식으로는  
 근본적으로 해결이 불가능하다.

#### **3.2 수능특강 PDF의 구조적 특징**

수능특강 PDF는 교육 평가용 문서의 특성상 텍스트와 시각 자료가 복잡하게 혼합된 **비정형·다층적 시각 구조**를 가진다. 이러한 구조적 특징은 시각장애 수험생의 점자·음성 기반 학습 과정에서 심각한 접근성 문제를 발생시키는 핵심 요인이 된다.

## **(1) 지문·문항·그래프가 한 페이지 내에 혼재된 복합 레이아웃**

수능특강 PDF는 일반적인 교과서나 직선적 문서와 달리, 하나의 페이지 안에

* **지문(text)**

* **문항 번호(item)**

* **선택지(choice)**

* **표(table)**

* **그래프(graph)**

* **도형(diagram)**

* **보조 설명문(footnotes, captions)**

* **강조 표시(밑줄·색 강조·박스)**

등이 동시에 배치된 \*\*멀티모달 레이아웃(multimodal layout)\*\*을 가진다.

이 구조는 페이지를 “위→아래” 순서로 읽는 것이 아니라,  
 **좌→우, 상→하, 지문→그래프→문항→선택지** 순으로 복합적으로 이동해야 한다.

비장애 학생은 시각적으로 페이지 전체를 즉시 스캔하며 필요한 정보에 빠르게 접근할 수 있지만,  
 시각장애 학생은 점자·음성 기반 선형 탐색 방식으로 인해  
 페이지를 처음부터 끝까지 순서대로 들어야 하므로 **지문·선택지·그래프 간 관계를 즉각적으로 이해할 수 없다.**

이 혼재 구조 자체가 접근성을 가장 크게 떨어뜨리는 요인이다.

## **(2) 시각적 배열(레이아웃)에 의미가 강하게 부여된 문서 구조**

수능특강 PDF에서는 다음과 같은 시각적 정보가 “문항 해결에 필요한 의미”로 사용된다.

* 지문 옆의 그래프: 지문의 특정 문단을 보조

* 문단 번호/소문: 지문 구조의 흐름을 나타냄

* 선택지 배치를 통해 비교 대상을 시각적으로 묶어줌

* 표의 행·열이 비교 구조를 형성

* 하이라이트·밑줄·강조 상자가 핵심 근거를 암시

즉, PDF는 **레이아웃 자체가 정보**이다.

하지만 점자·텍스트 변환에서는  
 이러한 시각적 신호가 모두 손실되며,  
 원본 문서의 의미 구조가 재현되지 않는다.

## **(3) PDF의 비정형 구조 때문에 점역·스크린리더가 구조를 복원하지 못함**

수능특강 PDF는 다음과 같은 이유로 구조적 파싱이 매우 어렵다.

### **✔ 텍스트와 이미지가 하나의 레이어에 섞여 있음**

OCR은 이를 분리하지 못해,  
 예를 들어 그래프 캡션이 선택지 사이에 끼어들거나,  
 문항 번호가 지문 중간에 섞이는 오류가 발생한다.

### **✔ 표·그래프는 실제 텍스트가 아니라 “이미지”로 포함**

→ 점역 과정에서 **표의 열·행 구조**,  
 → 그래프의 **좌표·증감 패턴**이 모두 사라진다.

### **✔ 문항 박스, 선택지 박스가 시각적으로만 구분됨**

→ 점자·음성 출력에서는 단일 텍스트 흐름으로 변환되며,  
 선택지 간 병렬 관계가 붕괴된다.

결과적으로 PDF의 시각적 레이아웃은 점역 시 모두 선형 텍스트로 평탄화되어,  
 문제 해결에 결정적인 **비선형 구조가 완전히 파괴되는 문제**가 발생한다.

## **(4) 선형 기반 점역 시 구조 붕괴 문제**

수능특강 PDF를 점자·텍스트로 선형 변환할 경우 다음 문제가 발생한다.

### **✔ 지문–문항–선택지의 관계가 단절됨**

지문과 문항이 서로 다른 순서로 섞여 출력되거나,  
 근거 문장 위치를 확인할 수 없게 된다.

### **✔ 그래프·표의 구조가 단순 문장 하나로 축소**

예:  
 “그래프가 증가하다가 감소한다.”  
 → 좌표, 교점, 극값 정보는 모두 소실.

### **✔ 선택지 비교를 위한 병렬 구조가 사라짐**

시각적으로 나란히 배치된 선택지가  
 점자/음성에서는 긴 텍스트 하나로 이어져 출력된다.

### **✔ 문단 구조·강조 구조가 보존되지 않음**

문단 기능, 전개 방식, 핵심 문장 등이 모두 연속 텍스트로 녹아들어  
 지문 구조를 파악하기 어려워진다.

이러한 구조 붕괴는 수능 핵심 역량인

* 정보 구조 파악

* 근거 기반 추론

* 선택지 비교

* 그래프 해석  
   을 모두 방해하여 시각장애 수험생이 **문항 해결 전략을 수립할 수 없게 만든다.**

#### **3.3 요구되는 기능 요구사항**

수능특강 PDF의 복합적 시각 구조와 시각장애 수험생의 선형 정보 처리 방식 간의 근본적 불일치를 해결하기 위해서는, 기존 점역·스크린리더 방식이 제공하지 못하는 새로운 형태의 학습 지원 기능이 필요하다. 본 절에서는 앞서 도출된 Pain Point와 PDF 구조 분석을 바탕으로, 본 연구가 해결해야 할 핵심 기능 요구사항을 정의한다.

## **(1) 의도 기반 정보 탐색(Intent-Based Information Retrieval)**

시각장애 수험생은 지문 전체를 순차적으로 듣거나 점자로 훑어야 하기 때문에,

* 특정 근거 문장,

* 조건,

* 예시,

* 그래프 관련 문장  
   등을 **빠르게 찾아가는 탐색 기능이 절대적으로 필요**하다.

기존 점역본은 문서 전체를 선형 텍스트로 변환하기 때문에  
 “근거가 있는 문단으로 바로 이동”  
 “조건이 언급된 부분만 듣기”  
 “그래프 참조 문장만 바로 탐색”  
 등이 불가능하다.

따라서 본 연구는 사용자의 의도(예: “근거 찾아줘”, “선택지 ③과 관련된 문장 어디?”)에 따라  
 문서를 구조적으로 탐색할 수 있는 **의도 기반 탐색 모델**이 요구된다.

## **(2) 비선형·구조적 정보 표현(Non-linear & Structural Representation)**

수능 지문과 문항은

* 문단 구조,

* 중심 문장,

* 논리 흐름,

* 선택지 비교 구조  
   등의 **비선형 시각적 구조**를 기반으로 구성된다.

하지만 점자·음성 기반 환경에서는 이러한 비선형 구조가 모두 선형 텍스트로 붕괴되어,  
 학습자가 문서 전체의 의미 구조를 이해하기 어렵다.

이에 따라 다음과 같은 기능이 필요하다.

* 문단 간 관계 구조 시각화(점자·음성 기반 구조 표현)

* 지문–문항–선택지 간 연결성 제공

* 선택지 병렬 비교를 위한 구조적 정보 제공

* 논리 구성 요소(가정·근거·반박·예외)의 의미 단위화

즉, 문서를 다시 “구조적으로 복원하는” 비선형 정보 모델이 필수적이다.

## **(3) 그래프 의미 추출(Graph Semantic Extraction)**

수능 수학 및 국어·영어 지문 내 시각자료는 문제 해결의 핵심 요소이지만,  
 기존 기술은 이를 단순 이미지나 설명 텍스트로만 처리해  
 **의미적 정보(증감 구간, 극값, 교점, 기울기)를 제공하지 못한다.**

따라서 다음과 같은 의미 중심 기능이 요구된다.

* 그래프/표 이미지 자동 식별

* 축·곡선·데이터 간 관계 추출

* 문제 해결에 필요한 핵심 요소만 의미 단위로 압축

* 점자/음성 적합 형태(청크형)로 변환

* 비교 그래프나 복합 그래프의 차이점 자동 해석

이는 단순 “그래프 읽기”가 아니라  
 **그래프를 문제 맥락에 맞게 이해시키는 기능**이 필요함을 의미한다.

## **(4) 어휘·근거 기반 탐색(Keyword/Evidence-Based Navigation)**

국어·영어 지문에서 시각장애 수험생은

* 중심 문장 찾기

* 의미 단락 구분

* 근거 문장 위치 파악  
   이 매우 어렵다.

따라서 다음 기능이 필수적이다.

* 핵심 어휘 자동 추출

* 문항-근거 문장 매핑

* 어휘 중요도 기반 설명

* 지문 내 특정 문장으로 바로 이동하는 “점프 탐색”

* 단어 뜻·용법·관계 표현(Pointing words) 자동 안내

즉, **문항 해결에 필요한 요소만 빠르게 접근 가능하게 하는 탐색 엔진**이 요구된다.

## **(5) 실시간 점자 출력(Real-Time Braille Output)**

수능특강/EBS 교재는 매년 새로운 문항이 포함되므로,  
 상황에 따라 즉시 점자 출력이 가능해야 한다.

기존 점자 학습기들은

* 대형·고가·정적 콘텐츠만 제공

* 업데이트 속도가 느림

* 점자 변환에 시간 지연 발생

등의 한계를 지닌다.

따라서 다음 요구사항이 필요하다.

* PDF 파싱 후 즉시 점자 청크 생성

* 그래프·지문·선택지별 실시간 점자 출력

* 3셀 점자 기반의 의미 압축 설계

* 점자 출력과 음성 출력의 동기화

* BLE 기반 저지연 통신 구조 구축

이는 기존 점자 교재와 접근성 기술이 제공하지 못하는  
 **동적·실시간 접근성**을 달성하는 핵심 요소이다.

## **요약: 본 연구에 요구되는 기능 5가지**

### **✔ 의도 기반 정보 탐색**

### **✔ 비선형·구조적 정보 복원**

### **✔ 그래프 의미 추출 알고리즘**

### **✔ 어휘/근거 기반 탐색**

### **✔ 실시간 점자 출력 파이프라인**

이 기능 요구사항들은 기존 점자·스크린리더·OCR 기반 접근성 기술로는  
 구현할 수 없는 새로운 정보 구조화 모델을 필요로 한다.

이 분석은 다음 장 **Ⅳ. 제안 시스템 설계**에서 실제 기술 구조로 이어진다.

#### **3.4 제안 시스템 요건 정의**

앞서 제시한 시각장애 수험생의 Pain Point와 수능특강 PDF의 구조적 한계를 해결하기 위해, 본 연구는 다음과 같은 \*\*핵심 시스템 요건(System Requirements)\*\*을 충족하는 접근성 기반 학습 플랫폼을 제안한다.

(1) 실시간 PDF 접근성 변환(Real-Time PDF Accessibility Transformation)

점역본 제공 지연(4–6개월) 문제를 해소하기 위해, 시스템은 수능특강 PDF가 공개되는 즉시  
 다음 과정을 자동으로 수행해야 한다.

* PDF에서 텍스트·이미지·표·그래프 요소 자동 분리

* OCR \+ 레이아웃 분석으로 문서의 의미 구조 복원

* 지문·문항·선택지·그래프를 문제 단위로 자동 재조직

* 점자·음성 학습에 적합한 **의미 기반 정보 청크** 생성

* 사용자 흐름에 맞춘 동적 콘텐츠 제공

즉, 기존 점역 방식처럼 정적 파일을 기다리는 것이 아니라,  
 **실시간 변환이 가능해야 한다는 것이 핵심 요건**이다.

## **(2) 비선형 구조 제공(Non-linear Structural Representation)**

수능 학습은 본질적으로

* 지문→문항

* 문항→근거

* 선택지→비교 구조

* 그래프→지문 연결  
   같이 **비선형 탐색**이 필수적이다.

따라서 제안 시스템은 다음을 만족해야 한다:

* 지문 전체의 구조(단락 기능, 전개 방식, 중심 문장)를 점자·음성 기반으로 재현

* 선택지 간 병렬 비교를 위한 구조적 표현 제공

* 문항-근거 문장 자동 매핑

* 그래프/표와 문항 간의 관계 연결

* 사용자 “의도 기반 탐색”이 가능한 구조적 정보 제공

즉, 단일 문자열로 읽는 “점자·음성 기반 선형 방식”을 넘어선  
 **비선형 정보 구조 복원**이 핵심 요건이다.

## **(3) 그래프를 의미 단위로 변환(Graph Semantic Encoding)**

시각자료는 문제 해결의 핵심 정보이지만 기존 방식에서는 구조가 완전히 상실된다.  
 따라서 제안 시스템은 다음을 충족해야 한다.

* 그래프/표 이미지 자동 탐지

* 좌표축·추세·증감 구간·극값·교점 등 의미 요소 자동 추출

* 문제 해결에 필요한 요소만 **의미 요약 청크 형태**로 변환

* 점자·음성으로 전달 가능한 symbolic representation 제공

* 복합 그래프(두 함수 비교 등)도 의미 단위로 비교 가능

즉, “그래프를 설명”하는 것을 넘어  
 **문제 해결에 필요한 의미 구조로 재구성하는 기능**이 필수적이다.

## **(4) 3셀 점자 소형 디바이스에서 정보 손실 최소화(Minimal-Loss Braille Encoding for 3-Cell Devices)**

대부분의 점자 연구는 32\~80셀의 대형·고가 디바이스를 가정하지만,  
 본 연구는 **저비용·휴대형 3셀 점자 디바이스**를 중심으로 한다.

따라서 다음 요건이 필수다:

* 긴 텍스트를 구조 단위로 쪼개어 점자 청크로 출력

* 중요한 정보(논리, 근거, 관계 구조)를 압축해 전달

* 그래프/표 개념을 3셀 단위로 표현할 수 있는 **semantic compression 모델**

* 점자 출력·음성 출력 간 동기화

* BLE 기반 저지연 통신으로 실시간 상호작용 지원

이 요건을 통해 저비용 디바이스에서도  
 **정보 손실을 최소화하고 학습 효율을 최대화하는 접근성 UX**를 달성해야 한다.

## **요약: 제안 시스템이 반드시 충족해야 할 4대 요건**

### **✔ 실시간 PDF → 접근성 변환**

### **✔ 비선형 “구조 기반” 정보 제공**

### **✔ 그래프 의미 분석·요약 제공**

### **✔ 3셀 점자 기반의 정보 손실 최소화**

## **제 4장 제안 시스템**

#### **4.1 시스템 개요**

본 연구는 수능특강 PDF를 기반으로 시각장애 수험생이 즉시 학습할 수 있도록,  
문서의 시각적 구조를 의미 기반 학습 단위로 자동 변환하고 이를 **점자·음성 기반 비선형 학습 환경**으로 제공하는 통합 시스템을 제안한다

제안 시스템은 다음과 같이  
**입력(PDF) → 전처리 → 구조 분석 → 과목별 의미 처리 → 점자·음성 출력**  
의 5단계 파이프라인으로 구성된다

## **(1) 입력 단계: PDF 교재 입력 (PDF Input Module)**

시스템은 수능특강 PDF 또는 교사용 PDF를 입력으로 받아 다음 요소를 수집한다.

* 텍스트 레이어

* 이미지 레이어 (그래프·표·도형)

* 페이지 레이아웃 정보 (위치·크기·배치)

* 시각적 강조 요소 (밑줄·색·박스 등)

PDF의 시각적 구조를 최대한 유지하면서,  
 문서 전부를 **디지털 분석 가능한 형태**로 로드한다.

## **(2) 전처리 단계: OCR·레이아웃 분석 기반 비정형 요소 분리 (Preprocessing Module)**

PDF 문서는 텍스트와 이미지 요소가 복합적으로 섞여 있기 때문에,  
 다음 전처리 과정을 수행한다.

* OCR 기반 텍스트 재인식 (누락·깨짐 보정)

* 그래프/표/도형 이미지 자동 추출

* 지문·문항·선택지 영역 분할(Layout Detection)

* 페이지 좌표를 활용한 정보 블록 단위화

이 단계에서는 PDF의 “표면 구조”를 분석 가능한 정보 단위로 재조정하여  
 후속 단계에서 의미 분석이 가능하도록 준비한다.

## **(3) 구조 분석 단계: 의미 기반 문서 재조직 (Structural Analysis Module)**

전처리된 정보는 문서의 의미 구조를 중심으로 다시 조직된다.

* 지문–문항–선택지 계층 구조 복원

* 문단 기능 분석 (서론–전개–근거–예시–반박 등)

* 문항 유형 분석(추론·적용·그래프 해석 등)

* 선택지 병렬 비교 구조 생성

* 근거 문장 자동 매핑

이 단계는 PDF의 시각적 레이아웃이 갖는 의미를  
 점자·음성 기반 학습에 적합한 **비선형 구조로 재해석하는 핵심 과정**이다.

## **(4) 과목별 의미 처리 단계 (Subject-Specific Processing Module)**

과목별로 요구되는 구조가 다르기 때문에,  
 국어·영어·수학 3개 모듈로 나누어 별도의 의미 분석을 수행한다.

### **국어/영어 모듈**

* 중심 문장·핵심 어휘·지문 논리 구조 분석

* 문항–근거 문장 연결

* 선택지 오답 논리 분석

* 논리 단위 기반 의미 청크 생성

### **수학 모듈**

* 그래프 의미 추출(증감 구간, 극값, 교점)

* 표/수열·함수 구조 분석

* 단위 변환, 좌표 관계 해석

* 문제 해결에 필요한 의미 요소만 요약한 symbolic encoding

각 과목별 처리 결과는 점자·음성 기반 학습에 최적화된  
 \*\*의미 기반 학습 단위(semantic learning chunks)\*\*로 변환된다.

## **(5) 출력 단계: 점자·음성 기반 비선형 학습 제공 (Braille & Audio Output Module)**

최종적으로 재조직된 정보는 시각장애 수험생에게 다음 방식으로 제공된다.

### **점자(3셀) 출력**

* 주요 의미 단위만 압축한 점자 청크

* 지문·문항 간 이동을 지원하는 점자 내비게이션

* 그래프 의미를 점자 패턴으로 표현하는 semantic compression

* BLE 기반 실시간 점자 업데이트

### **음성 출력(TTS/STT)**

* 전체 지문의 계층 구조를 비선형으로 탐색 가능

* 선택지 비교 기능(병렬 비교)

* 그래프 의미 설명 및 단계별 안내

* 질문/지시 기반 상호작용(“근거 찾아줘”, “③번 선택지 다시 비교”)

점자 출력과 음성 출력은 동기화되어,  
 사용자가 원하는 방식으로 **즉각적·비선형 정보 탐색**이 가능하다.

## **결론적으로, 제안 시스템은 다음과 같은 역할을 수행한다**

### **✔ 수능특강 PDF의 시각적 구조를**

→ 의미 기반 비선형 정보로 자동 재구성

### **✔ 텍스트·그래프·문항·선택지를**

→ 과목별 의미 단위로 다시 조직

### **✔ 점자(3셀)·음성 기반 완전한 학습 환경으로**

→ 실시간 제공

이는 기존 점역 시스템이나 스크린리더가 해결할 수 없던  
 수능특강 접근성 문제를 기술적으로 해결하는 새로운 학습 패러다임이다.

#### **4.2 전체 아키텍처**

제안 시스템은 크게  
 **① Frontend PWA**,  
 **② Backend 서버(Django \+ LLM \+ 분석 엔진)**,  
 **③ OCR/PDF·NLP·그래프 분석 모듈**,  
 **④ 3셀 점자 디바이스(BLE \+ Arduino 펌웨어)**  
 로 구성되는 **클라이언트–서버–하드웨어 통합 구조**를 가진다.

사용 흐름은 다음과 같다.

**수능특강 PDF 업로드 → 백엔드에서 PDF/OCR/구조 분석 → 과목별 의미 처리(NLP/그래프 분석) →**  
 **Braille Engine이 3셀용 점자 청크 생성 → Frontend(PWA)가 음성 안내 \+ BLE를 통해 점자 디바이스 제어**

아래에서는 각 컴포넌트별 역할과 상호작용을 정리한다.

### **4.2.1 Frontend (PWA \+ STT/TTS \+ BLE)**

Frontend는 \*\*스마트폰 기반 PWA(Progressive Web App)\*\*로 구현되며,  
 시각장애 수험생이 실제로 상호작용하는 주 인터페이스 역할을 한다.

* **PWA 구조**

  * 브라우저 설치형이 아닌, 홈 화면에 추가하여 앱처럼 사용하는 형태

  * 오프라인 일부 동작, 푸시, 백그라운드 동기화 등 활용 가능

* **TTS(Text-to-Speech)**

  * 백엔드에서 전달된 지문·문항·그래프 설명을 음성으로 출력

  * 점자 청크 전환 시, 현재 무엇을 출력하고 있는지 음성으로 안내

* **STT(Speech-to-Text)**

  * 사용자가 “근거 문장 알려줘”, “3번 선택지 다시”, “그래프 설명 다시” 등  
     음성 명령으로 탐색을 수행할 수 있게 함 → **의도 기반 정보 탐색** 구현

* **BLE(Web Bluetooth)**

  * 브라우저에서 직접 BLE 디바이스(3셀 점자 단말)와 연결

  * 점자 청크를 패킷으로 전송하여 **실시간 점자 출력** 제어

  * 버튼/센서 입력(예: 다음/이전, 재출력 등)을 다시 PWA로 전달하여 양방향 상호작용

Frontend는 단순 뷰어가 아니라,  
 **“음성+점자 기반 비선형 내비게이션 허브”** 역할을 수행한다.

### **4.2.2 Backend (Django \+ LLM \+ Graph Analyzer)**

Backend는 **Django 기반 REST API 서버**로 구현되며,  
 전체 “두뇌(brain)” 역할을 하는 분석·변환·관리 기능을 담당한다.

* **Django API 서버**

  * PDF 업로드/관리 API

  * 지문/문항/그래프 분석 결과 조회 API

  * 점자 청크 요청/응답 API

  * 학습 이력 및 오답/약점 로그 관리

* **LLM 연동 모듈**

  * 지문 요약(문항 중심 요약)

  * 문항–근거 문장 매핑

  * 선택지 오답 논리 분석

  * 학습자 수준에 따른 설명 난이도 조절 등

* **Graph Analyzer 연동**

  * 그래프 이미지 파일을 받아 의미 요소(증감, 극값, 교점, 구간 특성 등)로 변환

  * 이 결과를 Braille Engine과 NLP 모듈에 전달해  
     \*\*“그래프 의미 청크”\*\*를 생성하는 데 사용

Backend는 프론트에서 들어오는 요청(“이 문제의 그래프 설명 줘”, “근거 문장 점자 출력해줘”)을 받아,  
 NLP/그래프/Braille Engine을 호출한 뒤 결과를 다시 PWA로 반환한다.

### **4.2.3 OCR/PDF Parser 모듈**

이 모듈은 **수능특강 PDF를 기계가 이해 가능한 구조**로 바꾸는 역할을 한다.

* PDF에서

  * 텍스트 레이어 추출

  * 이미지(그래프·표·도형) 영역 탐지

  * 문단/박스/번호/선택지 영역 레이아웃 분석

* OCR(문자인식)

  * 텍스트가 이미지 형태로 포함된 경우 재인식

  * 그래프/표 캡션, 작은 글자, 번호 등 OCR로 보정

* 블록 구조화

  * “지문 블록 / 문항 블록 / 선택지 블록 / 그래프 블록 / 표 블록”으로 분할

  * 페이지 좌표 정보를 함께 저장하여 이후 **구조 분석 모듈**에서  
     지문–그래프–문항 간 위치 관계를 복원할 수 있게 함

이 단계에서 PDF는 더 이상 단순 파일이 아니라,  
 \*\*“분석 가능한 학습 단위들의 집합”\*\*으로 바뀐다.

### **4.2.4 NLP 기반 지문 분석 모듈**

이 모듈은 LLM 및 전통적 NLP 기법을 활용해  
 **국어·영어 지문과 문항을 의미 구조 중심으로 분석**한다.

* 문단 단위 분할 및 기능 분석

  * 도입/전개/예시/결론, 주장·근거·반박 등 레이블링

* 중심 문장/핵심 어휘 추출

  * 문항에서 요구하는 정보와 직접 연결되는 문장 탐색

* 문항–근거 문장 매핑

  * 각 선택지가 의존하는 지문 위치를 추정

  * “이 선택지를 판단하려면 어느 문장을 봐야 하는지”를 구조적으로 연결

* 문항 유형 분류

  * 추론형, 내용일치형, 어휘/표현형, 자료해석형 등

* **출력**

  * 점자/음성에 적합한 “지문 구조 요약”

  * 근거 문장 목록, 중요 문장 리스트

  * 선택지별 설명용 문장 청크

이 모듈에서 나온 결과는 이후 **Braille Engine**으로 넘어가  
 3셀 점자용 의미 청크로 압축된다.

### **4.2.5 그래프 분석 엔진 (Graph Analysis Engine)**

그래프 분석 엔진은 **그래프·표·도형 이미지에 특화된 의미 해석 모듈**이다.

* 입력: OCR/PDF 파서에서 분리된 그래프(이미지)

* 처리:

  * 축 위치/범위 추정

  * 곡선/막대/점 데이터 추출

  * 증가/감소 구간, 극대·극소, 교점, 추세 등 의미 요소 감지

  * 표의 경우 행·열 구조와 값 관계 분석

* 출력:

  * “이 함수는 x가 증가할수록 처음에는 증가하다가 이후 감소한다.”

  * “두 그래프는 x \= 2에서 교차한다.”

  * “최대값은 x \= 1에서 y \= 3이다.”  
     와 같이 **문제 해결에 직접 필요한 정보만 요약한 의미 표현**

이 의미 표현은 NLP 모듈·LLM과 함께 후처리되어,  
 **점자/음성용 그래프 설명 청크**로 변환된다.

### **4.2.6 Braille Engine (3셀 점자 청크 변환)**

Braille Engine은 이 시스템의 핵심 중 하나로,  
 모든 분석 결과를 **3셀 점자 디바이스에 맞는 단위로 압축·인코딩**하는 역할을 한다.

* 입력:

  * 지문 구조 요약 (문단/핵심 문장)

  * 문항–근거 연결 정보

  * 그래프 의미 표현

  * 선택지 비교 정보

* 처리:

  * 긴 문장을 “점자 청크” 기준으로 분할

  * 중요도/구조 정보를 우선순위로 압축

  * 3셀에 표현 가능한 심볼/패턴 정의 (예: 구조 마크, 구분자, 강조 패턴 등)

  * 점자 디바이스로 보낼 **패킷 시퀀스 생성**

* 출력:

  * PWA가 BLE로 전송 가능한 점자 데이터 스트림

  * 점자–음성 동기화를 위한 메타데이터(현재 위치, 청크 ID 등)

Braille Engine은 단순 변환이 아니라,  
 **“어떤 정보를 먼저, 어떻게 압축해서 보여줄 것인가”를 결정하는 의미 압축 코어**이다.

### **4.2.7 점자 디바이스 하드웨어 구조 (BLE → Arduino → 3셀 점자)**

하드웨어는 **소형 3셀 점자 디바이스**로 구성되며,  
 BLE 통신 모듈과 Arduino 계열 MCU를 중심으로 동작한다.

* **BLE 모듈**

  * 스마트폰 PWA와 페어링

  * 점자 데이터 패킷 수신

  * 패킷을 Arduino로 전달

* **Arduino MCU**

  * 수신된 패킷을 파싱하여 각 셀(6점) on/off 제어 신호로 변환

  * 타이밍(출력 유지 시간, 전환 속도) 관리

  * 버튼/터치 입력(다음/이전, 반복 출력 등)을 다시 BLE로 전송

* **3셀 점자 출력부**

  * 각 셀별 6점(또는 8점) 솔레노이드/핀 구동

  * 저전력·휴대용을 가정한 설계

  * 사용자가 한 손 또는 양 손으로 촉지하며 학습 가능

이 하드웨어 계층 덕분에,  
 **“스마트폰 \+ 소형 점자 단말”만 있어도 수능특강 PDF를 학습할 수 있는 구조**가 완성된다.

#### **4.3 과목별 처리 흐름**

### **4.3.1 국어 (Korean Language Module)**

국어 지문은 논리적 구성(서론–전개–결론), 중심문장, 근거 구조 등 **비선형적 의미 관계**가 강하게 나타나는 과목으로,  
 시각장애 수험생이 선형 기반 점자·음성 환경에서 접근하기 가장 어려운 영역이다.  
 따라서 본 시스템은 국어 지문 분석을 위해 **지문 구조 분석 → 핵심 문장 추출 → 근거 매핑**의 3단계 파이프라인을 제안한다.

## **(1) 지문 구조 분석 (Discourse & Paragraph Structure Analysis)**

이 단계는 PDF 지문을 단순 텍스트로 처리하는 것이 아니라,  
 “문제가 어떻게 구성되어 있는지”를 기계가 이해하도록 재조직하는 과정이다.

### **주요 처리 내용**

* **문단 단위 분할**  
   OCR/PDF 파서에서 추출된 텍스트를 문단 간 공백·번호·위치 기반으로 재구성한다.

* **문단 기능 레이블링(LLM 기반)**  
   각 문단을 다음과 같은 기능으로 자동 분류한다.

  * 도입/배경 제시

  * 개념 정의

  * 예시/근거 제시

  * 비교/대조

  * 반론 제시

  * 결론/요약

* **지문 전개 구조 그래프 생성**  
   문단 간 관계(→ 전개, ← 근거, ↔ 비교)를 그래프로 모델링하여,  
   점자/음성 기반으로도 “가장 중요한 문단 흐름”을 탐색할 수 있도록 구조화한다.

### **의의**

이 단계에서 지문을 “선형 텍스트”가 아닌  
 **의미 구조를 가진 비선형 그래프**로 재조직함으로써  
 시각장애 수험생이 음성·점자로도 “지문 전체 흐름을 한눈에 이해”할 수 있게 된다.

## **(2) 핵심 문장 추출 (Key-Sentence Extraction)**

국어 지문에서 문제를 풀기 위해 필요한 문장은 전체 문장의 일부에 불과하다.  
 따라서 시스템은 NLP/LLM 기반으로 다음 정보를 탐지하여 핵심 문장 세트를 생성한다.

### **핵심 문장 추출 알고리즘**

* **문항 키워드 기반 매칭**  
   문항에서 등장하는 핵심 개념, 조건, 단서를 지문 내 어휘와 비교하여  
   연관성이 높은 문장을 우선적으로 선정

* **중심 문장 탐지 모델**  
   문단 내 논리 중심에 위치하는 문장 탐지  
   (예: 관계어 기반 “따라서”, “즉”, “결국”, “하지만”)

* **개념–예시–근거 연쇄 탐지**  
   하나의 논리 단위를 이루는 문장 그룹을 묶어  
   “의미 단위 청크”로 변환

### **출력 형태**

* 핵심 문장 목록

* 중요도 점수(LLM 기반)

* 문항과의 관련도 매트릭스

* 점자/음성 출력용 요약 청크 생성

### **의의**

이 처리는  
 “전체 지문을 맹목적으로 읽지 않고,  
 문제 해결에 필요한 부분만 비선형적으로 탐색할 수 있게 한다.”  
 즉, 시각장애 수험생의 **정보 처리 속도를 획기적으로 높이는 핵심 기능**이다.

## **(3) 근거 매핑 (Evidence Mapping for Question-Answering)**

수능 국어에서 가장 중요한 부분 중 하나가  
 **문항의 근거 문장을 지문에서 정확히 찾는 것**이다.

비장애 수험생은 눈으로 스캔하며 찾을 수 있지만,  
 시각장애 수험생은 수십 문장을 순차적으로 들어야 하기 때문에  
 해결 속도가 극단적으로 느려진다.

본 시스템은 이를 해결하기 위해 \*\*문항–지문 근거 매핑(Evidence Alignment)\*\*을 수행한다.

### **근거 매핑 절차**

* **문항 분석**  
   문항에서 요구하는 조건·관계·어휘·문장 유형을 구조화한다.  
   (예: “내용 일치형”, “관계 파악형”, “적용형”)

* **LLM 기반 의미 유사도 계산**  
   문항 의미와 지문 각 문장의 의미 벡터를 비교하여  
   근거가 될 가능성이 높은 후보 문장 탐색

* **답 선택지별 근거 문장 분리**

  * 선택지 ① → 관련 근거 문장 2\~3개

  * 선택지 ② → 관련 근거 문장 1개

  * …  
     이렇게 선택지별로 “논리 기반 청크”를 생성한다.

* **근거-오답 연결도 생성**  
   선택지에서 틀린 부분이 무엇인지 설명하기 위한  
   오답 논리 근거도 함께 추출한다.

### **출력 형태**

* 문항-근거 매핑 테이블

* 선택지별 근거 리스트

* 점자 청크 및 음성 설명으로 변환 가능한 “근거 단위 패키지”

### **의의**

이 기능은 시각장애 수험생에게  
 “내가 왜 이 선택지가 정답인지 / 오답인지”를  
 점자·음성으로 빠르게 제공할 수 있는 **수능형 비선형 내비게이션 구조**를 제공한다.

## **국어 처리 흐름 요약**

| 단계 | 설명 | 출력 |
| ----- | ----- | ----- |
| 지문 구조 분석 | 문단 기능·논리 흐름 분석 | 지문 구조 그래프 |
| 핵심 문장 추출 | 문항 기반 핵심 문장 필터링 | 핵심 문장 청크 |
| 근거 매핑 | 선택지 별 근거 문장 연결 | 근거 매핑 테이블 |

이 결과는 **Braille Engine**으로 전달되어 3셀 점자 청크로 변환되며  
 음성 안내와 동기화되어 시각장애 수험생이  
 지문·문항을 “비선형 구조”로 탐색할 수 있도록 제공된다.

### **4.3.2 영어 (English Language Module)**

수능 영어 지문은 논리적 연결성, 문장 간 의미적 참조, 선택지 패러프레이즈(paraphrase) 구조가 강하게 나타나는 과목으로, 시각장애 수험생이 점자·음성 기반 선형 읽기로 접근하기 가장 부담이 큰 영역 중 하나이다.  
본 연구는 이러한 특성을 해결하기 위해 **논리 구조 분석 → 핵심 문장 추출 → 선택지 비교 → 지문-문항 대응**의 4단계 파이프라인을 설계하였다.

## **(1) 논리 구조 분석 (Logical Structure Analysis)**

영어 지문은 문단 구조보다 \*\*문장 간 논리 연결( coherence )\*\*이 중요하다.  
 따라서 시스템은 문장 단위의 의미 관계를 분석해 논리 지도를 생성한다.

### **주요 처리 내용**

* **문장 분할 (Sentence Splitting)**  
   OCR/텍스트 블록을 정제하고, 지문 전체를 문장 단위로 분할한다.

* **논리 연결어 분석 (Discourse Marker Detection)**  
   다음과 같은 연결어를 기반으로 문장의 기능을 자동 레이블링한다.

  * 원인/결과: therefore, thus, because

  * 대조: however, nevertheless, on the contrary

  * 추가: moreover, in addition

  * 예시: for example, such as

* **문장 간 의미 관계 그래프 생성**  
   각 문장을 노드로, 의미 연결을 에지로 구축하여  
   지문 전체의 “논리 구조 그래프(logical structure graph)”를 만든다.

* **주장–근거–예시 체계 탐지**  
   claim → evidence → elaboration 같은  
   영어 지문만의 기본 템플릿을 자동 분석한다.

### **출력**

* 지문 논리 구조 그래프

* 문장 유형 레이블(주장/근거/예시/전환 등)

### **의의**

시각장애 수험생이 음성/점자 기반으로도 지문 전체의 논리 흐름을 이해할 수 있도록  
 **비선형 탐색의 토대**를 만든다.

## **(2) 핵심 문장 추출 (Key-Sentence Identification)**

영어 지문은 핵심 문장이 비교적 명확하지만,  
 시각장애 수험생은 전체 지문을 순차적으로 들어야 하기 때문에  
 핵심 문장을 빠르게 탐지하는 기능이 반드시 필요하다.

### **핵심 문장 추출 방법**

* **문항 키워드 기반 필터링**  
   문항에서 언급된 주제어(topic words)와 지문 문장 간 유사도 분석

* **관계어 기반 중요도 측정**  
   therefore, thus, in summary 등 결론 신호어에 높은 가중치 부여

* **패러프레이즈 탐지(LLM 기반)**  
   선택지에서 변형된 문장이 지문의 어떤 부분을 재구성한 것인지 매핑

* **지문 중심 내용(topic sentence) 탐지**  
   첫 문장/마지막 문장/전환부 문장의 논리적 중심성 분석

### **출력**

* 핵심 문장 리스트

* 중요도 스코어

* 선택지와의 매핑 정보 포함

### **의의**

국어와 달리 영어는 “핵심 문장 \= 정답 근거” 비율이 매우 높기 때문에,  
 이 단계가 시각장애 수험생의 정답률과 풀이시간에 직접적인 영향을 준다.

## **(3) 선택지 비교 (Choice Comparison & Paraphrase Analysis)**

수능 영어의 결정적 난제는  
 **선택지 문장이 지문 문장을 패러프레이즈(paraphrase)하여 변형해 놓는다는 점**이다.  
 비장애 수험생은 시각적으로 선택지들을 병렬 비교할 수 있지만,  
 시각장애 수험생은 순서대로 음성으로 듣기 때문에  
 차이를 파악하기 매우 어렵다.

이를 해결하기 위해 본 시스템은 다음을 수행한다.

### **선택지 의미 분석**

* 선택지 문장을 문법적/논리적 단위로 분해

* 핵심 의미 요소(topic, predicate, relation) 추출

* 부정/강조/조건 변형 탐지(예: "not", "only", "unless", "hardly")

### **지문-선택지 의미 유사도 분석**

* BERT/LLM 기반 의미 벡터 비교

* 패러프레이즈 여부 판단

* 지문 문장에서 바뀐 부분만 하이라이트(음성/점자 형태로 제공)

### **선택지 간 차이 비교**

* 시각적 비교가 불가능한 상황을 고려해  
   “병렬 구조 청크”로 변환하여 점자·음성으로 비교 제공

* 예:

  * **①** A happens because B.

  * **②** A happens despite B.  
     → 핵심 관계어( because vs despite )만 점자/음성으로 강조 출력

### **출력**

* 선택지 간 차이 비교표

* 지문 대비 패러프레이즈 매핑

* 핵심 변형 포인트(negation, quantifier, relation) 요약 청크

### **의의**

시각장애 수험생이 **선택지 대조 문제를 점자·음성 기반 환경에서도 공평하게 수행**할 수 있도록 한다.

## **(4) 지문–문항 대응 (Passage–Question Alignment)**

영어 지문의 대부분 문항은  
 “이 선택지는 어느 문장(또는 어느 문단)을 기반으로 판단하는가?”가 핵심이다.

본 시스템은 다음 흐름으로 대응 관계를 자동 분석한다.

### **문항 의미 구조 분석**

* 문항이 요구하는 작업 유형 파악

  * inference(추론)

  * detail question(세부 내용)

  * main idea(주제)

  * purpose/attitude

  * flow(문장 삽입)

### **지문 문장들과 의미 매핑**

* 문항 요구 의미와 지문 문장 의미 벡터 비교

* 근거 가능성이 높은 문장 후보군 탐지

* 필요 시 문장 연결(2–3문장 청크)도 반환

### **문항 유형별 최종 근거 구조 생성**

* Detail: 특정 한 문장

* 추론: 두 문장 이상의 관계

* 삽입 문제: 앞·뒤 문장의 논리 관계 분석

* 제목/주제: 중심 문장 집합 기반 결정

### **출력**

* 문항–근거 매핑 테이블

* 각 선택지와 가장 관련 있는 지문 문장 청크

* 점자·음성 출력용 구조 패키지

### **의의**

영어 문제 특성상 “정답=지문의 특정 의미 요소”이므로,  
 이 대응 분석은 시각장애 수험생의 이해도와 풀이 속도를 극적으로 향상시키는 핵심 기능이다.

## **영어 처리 흐름 요약**

| 단계 | 설명 | 출력 |
| ----- | ----- | ----- |
| 논리 구조 분석 | 문장 간 의미 관계 분석 | 논리 구조 그래프 |
| 핵심 문장 추출 | 지문 전체에서 주요 문장 필터링 | 핵심 문장 청크 |
| 선택지 비교 | 패러프레이즈·부정·관계 분석 | 선택지 비교 청크 |
| 지문–문항 대응 | 문항 유형 기반 근거 매핑 | Q–A 매핑 테이블 |

이 출력 결과는 모두 **Braille Engine → 3셀 점자 청크 → 음성 안내**로 연결된다.

### **4.3.3 수학 (Math Module)**

*그래프 의미 분석 \+ symbolic encoding \+ 표/함수 처리*

수능 수학은 그래프·표·함수·수식 등 **시각적·비정형 정보**가 문제 해결의 핵심이며, 기존 점자·스크린리더 방식으로는 구조를 재현할 수 없다.  
 본 연구는 수학 문제를 처리하기 위한 핵심 파이프라인으로  
 **(1) 그래프 의미 분석 → (2) symbolic encoding → (3) 표/함수 구조 분석 → (4) 점자·음성 출력 변환**  
 을 제안한다.

# **(1) 그래프 의미 분석 (Graph Semantic Extraction)**

그래프 이미지는 PDF 내에서 비텍스트(이미지)로 존재하기 때문에 단순 OCR로는 의미를 추출할 수 없다.  
 따라서 본 시스템은 Computer Vision 기반 분석 \+ LLM 기반 의미 보정 방식의 하이브리드 접근을 사용한다.

### **① 좌표계 탐지**

* x축, y축의 직선 구조 검출(Hough Transform 기반)

* 좌표 범위 추정(눈금 인식 또는 레이블 OCR)

* 원점, 축의 방향성 식별

### **② 곡선/막대/점 데이터 추출**

* 그래프 종류 분류(Function → Line graph, Bar graph, Scatter 등)

* 함수 곡선 픽셀 추출 후 smoothing

* 주요 포인트 자동 추출

  * 극대/극소

  * 교점

  * 증가/감소 구간의 변화 시점

  * 근사 기울기 변화 포인트

### **③ 의미 요소(semantic elements) 생성**

그래프 자체를 그대로 설명하는 것이 아니라,  
 문제를 풀기 위해 필요한 최소 의미 요소로 압축한다.

* 증가/감소 구간

* 최대값/최소값

* 교점의 x좌표

* 기울기 변화(증가→감소, 감소→증가)

* y절편, x절편

* 영역 비교(두 그래프 사이의 상대적 크기)

### **④ LLM 기반 의미 보정**

CV가 추출한 요소를 LLM이 재해석하여  
 수능 문항에 맞는 표현으로 의미 정제한다.

예:  
 “x=1에서 y값이 최대 근처” → “이 함수는 x=1에서 최대값을 가진다.”

# **(2) Symbolic Encoding (그래프→점자/음성용 구조 표현)**

그래프는 시각 중심 정보이기 때문에  
 이를 점자 3셀로 표현하려면 **상징적(symbolic)·요약적(abstract)** 표현이 필요하다.

본 연구는 다음 인코딩 원리를 제안한다.

### **① 의미 단위 청크 생성**

그래프 의미 요소를 다음 구조로 나눔:

* 전반 구조 청크(“증가 후 감소하는 형태”)

* 주요 포인트 청크(“극대값은 x=2에서”)

* 비교 청크(“A 그래프는 B 그래프보다 항상 크다”)

* 조건 청크(“x≥3에서 값이 0보다 작음”)

청크는 점자·음성 간 싱크된다.

### **② symbolic 패턴 인코딩**

점자 3셀의 한계(18점)를 고려하여 **의미 코드** 기반 변환을 수행한다.

예:

* ⠮ 증가 구간

* ⠯ 감소 구간

* ⠟ 극대 포인트 표시

* ⠷ 극소 포인트 표시

* ⠾ 교점 표시

예시 출력:

“증가⠮ | x=1 극대⠟ | 이후 감소⠯”

### **③ 수능형 그래프 패턴 사전 적용**

수능에서 자주 등장하는 패턴을 미리 인코딩:

* 이차함수 모양

* 절댓값 그래프

* 지수 증가/감소

* 로그함수 완만형

* 삼각함수 패턴  
   → 점자 출력에서 인식 가능한 패턴 제공

# **(3) 표/함수 구조 분석 (Table & Function Analysis)**

### **① 표(Table) 구조 분석**

* 행(row), 열(column) 인식

* 패턴 분석: 증가/감소, 비교, 최대·최소

* 관계성 추출:

  * “A열이 증가할수록 B열은 감소한다”

  * “3행에서 값이 가장 크다”

### **② 함수(Function) 구조 분석**

수능에서 함수 문제는 대부분 다음 의미 요소로 구성된다:

* 정의역/치역

* 단조성

* 연속성 여부

* 기울기 변화

* 극값

* 부등식 판정

* 절댓값/합성함수 등 변형

이를 기반으로 **함수 의미 그래프**를 생성한다.

### **③ 수식(si) 파싱**

* OCR 기반 수식 파싱

* 수식 트리(Expression Tree) 생성

* 수능형 단순화(동치 변환 등)

### **출력**

* 표 구조 요약 청크

* 함수 의미 요약(증감/극값/교점)

* 수식 구조 압축 표현

# **(4) 점자·음성 출력 변환 (Braille & Speech Rendering)**

수학 정보는 국·영과 다르게 **모든 요소가 구조적**이기 때문에  
 다음 원칙으로 출력한다.

## **① 점자 출력(Braille Rendering)**

* 그래프/표/함수 각각을 “의미 단위 점자 청크”로 출력

* 3셀의 물리적 제약을 고려하여

  * 주요 의미만 압축

  * 구조 코드(symbolic code)로 구분

* 사용자가 “다음/이전” 버튼으로 청크 이동 가능

예 출력:

“증가⠮ → x=2 극대⠟ → 감소⠯”

이 출력 패턴은 시각 대신 **촉각 기반 그래프 이해**를 가능하게 한다.

## **② 음성 출력(Audio Rendering)**

* 점자 청크와 음성 설명을 동일한 의미 구조로 맞춤

* 그래프 의미를 풀어서 설명

* 표/함수의 조건을 단계적으로 안내

* 사용자의 명령(STT):

  * “극대 다시”

  * “증가 구간만 설명”

  * “표 비교 다시”

# **수학 처리 흐름 요약**

| 단계 | 설명 | 출력 |
| ----- | ----- | ----- |
| 그래프 의미 분석 | CV \+ LLM 기반 구간/극값/교점 추출 | 그래프 의미 요소 |
| symbolic encoding | 의미 요소를 점자/음성용 코드로 변환 | semantic code 청크 |
| 표/함수 분석 | 표/함수의 구조·관계 파악 | 표/함수 의미 청크 |
| 점자/음성 출력 | 점자 3셀 출력 \+ 음성 안내 싱크 | 최종 학습 출력 |

**4.3.4 핵심 알고리**

본 절에서는 제안 시스템을 구성하는 다섯 가지 핵심 알고리즘, 즉  
 ① 문항-근거 매핑, ② 선택지 논리구조 분석, ③ 그래프 의미 압축,  
 ④ 점자 청크 인코딩, ⑤ 학습 로그 기반 개인화 모델  
 의 설계 원리와 처리 절차를 기술한다. 이 알고리즘들은 단순 정보 변환을 넘어,  
 시각장애 수험생의 시험·학습 상황에 특화된 의미 기반 접근성 모델을 구현하는 핵심 요소이다.

## 4.1 문항-근거 매핑 알고리즘 (Question–Evidence Mapping)

문항-근거 매핑 알고리즘은 각 문항이 지문·그래프·표의 어느 부분을 근거로 하는지를 자동으로 연결하는 알고리즘으로,  
 시각장애 수험생이 “정답의 근거가 어디에 있는지”를 빠르게 탐색할 수 있도록 지원한다.

### (1) 입력 및 전처리

* 입력:

  * 지문 문장 리스트 {S₁, S₂, …, Sₙ}

  * 문항 텍스트 Q

  * 선택지 리스트 {C₁, C₂, …, Cₖ}

* 전처리:

  * 형태소 분석 / 토큰화

  * 불용어 제거, 핵심 어휘(명사, 동사, 연결어 등) 추출

  * 임베딩(embedding) 벡터 생성 (LLM 또는 BERT 기반)

### (2) 문항–지문 의미 유사도 계산

각 문장 Sᵢ와 문항 Q 사이의 의미 유사도를 코사인 유사도 또는 LLM 기반 점수로 계산한다.  
 유사도가 일정 기준 이상인 문장을 1차 근거 후보 집합으로 선정한다.

* score(Q, Sᵢ) ≥ θ₁ → 후보 근거 문장으로 포함

추가적으로, 문항이 요구하는 작업 유형(내용일치, 추론, 태도, 제목 등)을 LLM으로 분류하여  
 추론형인 경우에는 \*\*두 개 이상의 문장 연쇄( Sᵢ, Sⱼ )\*\*를 함께 고려한다.

### (3) 선택지별 세부 근거 연결

각 선택지 Cⱼ 에 대해서도 지문 문장들과 의미 유사도를 계산하고,

* Cⱼ 와 가장 밀접한 문장 집합 Eⱼ \= {Sₐ, Sᵦ, …}  
   을 생성한다. 이때,

* Q ↔ Sᵢ

* Cⱼ ↔ Sᵢ  
   두 방향의 매핑을 모두 고려해 교집합/합집합을 통해 최종 근거 세트를 정제한다.

### (4) 출력 구조

* 문항별 근거 문장 목록

* 선택지별 근거 매핑 (정답/오답 선택지 모두)

* 점자/음성 출력용 “근거 청크 패키지”

이 알고리즘은 시각장애 수험생에게  
 “이 선택지를 판단하려면 이 문장(또는 문장 묶음)을 보면 된다”는  
 비선형 탐색 포인트를 제공한다는 점에서 기존 방식과 차별화된다.

## 4.2 선택지 논리구조 분석 (Choice Logic Structure Analysis)

선택지 논리구조 분석 알고리즘은 각 선택지가  
 지문의 어느 부분을 어떻게 변형·왜곡·요약하고 있는지를 구조적으로 분석해,  
 시각장애 수험생이 선택지 간 차이를 점자·음성 기반으로도 명확히 비교할 수 있게 한다.

### (1) 선택지 문장 구조 파싱

각 선택지 Cⱼ 에 대해 다음을 수행한다.

* 구문 분석(Dependency Parsing)

* 논리 구조 추출

  * 주어–술어–목적어

  * 부정( not, never, hardly )

  * 양화사( all, some, most )

  * 조건( if, unless )

  * 인과( because, so, therefore )

이를 통해 선택지마다 \*\*논리 프레임(logical frame)\*\*을 생성한다.

예:

* “All experiments support the claim.”  
   → \[양화사: all\] \+ \[관계: support\]

* “Some experiments contradict the claim.”  
   → \[양화사: some\] \+ \[관계: contradict\]

### (2) 지문 의미와의 대응

4.1에서 계산한 문항–근거 매핑 결과를 활용하여,  
 각 선택지가 참조하는 지문 문장과 의미를 비교한다.

* 선택지 Cⱼ 의 논리 프레임 vs 근거 문장 Sᵢ 의 논리 프레임

* 일치/불일치/과장/축소/역전 등의 패턴 감지

### (3) 선택지 간 차이 강조

선택지들 사이에서

* 양화사 차이(all vs some)

* 부정 유무(“not”, “never”)

* 인과 관계 뒤집기(because ↔ despite)  
   등이 발생하면 이를 “핵심 변형 포인트”로 추출한다.

이 정보는 점자·음성 출력 시,

* “①은 all, ②는 some, ③은 not을 포함한다”  
   처럼 비교 중심 청크로 변환된다.

### (4) 출력

* 선택지별 논리 구조 요약

* 선택지 간 차이 포인트 리스트

* 점자/음성용 비교 청크

이 알고리즘은 선택지 간 대조를 눈으로 볼 수 없는 상황에서도  
 선택지의 논리적 차이를 촉각·청각 기반으로 명확히 전달한다는 점에서 의미가 크다.

## 4.3 그래프 의미 압축 알고리즘 (Graph Semantic Compression)

그래프 의미 압축 알고리즘은  
 수학/국어/영어 지문 속 그래프·도형·표를  
 문제 해결에 필요한 의미 단위로 줄여서 표현하는 알고리즘이다.

### (1) 의미 요소 추출

그래프 분석 엔진(3.3에서 설명)으로부터 다음과 같은 요소를 입력받는다.

* 증가/감소 구간

* 극대/극소 위치

* 교점 좌표 또는 위치

* y절편, x절편

* 두 그래프 간 상대적 크기

* 특정 구간에서의 부호(양/음)

### (2) 중요도 기반 필터링

문항 텍스트와 함께 LLM에 전달하여,  
 어떤 의미 요소가 실제로 정답 판단에 필요하고,  
 어떤 요소는 불필요한 디테일인지 중요도를 평가한다.

* score\_importance(elementᵢ | 문항) ≥ θ₂ 인 요소만 남김  
   → 불필요한 시각 정보(장식, 부차적 패턴 등) 제거

### (3) 계층적 의미 압축

남은 의미 요소들을

* 전체 패턴(전반 구조)

* 국소 정보(특정 x에서의 값, 극값 등)

* 관계 정보(두 함수 비교)  
   의 3계층으로 나눠 배열한다.

예:  
 1단계: “이 함수는 증가 후 감소하는 형태이다.”  
 2단계: “x=2에서 최대값을 가진다.”  
 3단계: “x\>3에서 다른 그래프보다 항상 작다.”

### (4) 출력

* 계층화된 의미 청크 리스트

* 각 청크의 우선순위/요약도 메타데이터  
   → 이후 점자·음성 인코딩 모듈에서 사용

이 알고리즘의 핵심은  
 그래프를 ‘보여주는’ 것이 아니라,  
 그래프가 문제에서 맡은 역할만 골라 ‘설명하는’ 것이다.

## **4.4 점자 청크 인코딩 방식 (Braille Chunk Encoding)**

점자 청크 인코딩 알고리즘은  
 위에서 생성된 의미 청크들을 **3셀 점자 디바이스에 적합한 단위로 쪼개고,**  
 **특정 패턴으로 인코딩하는 규칙**을 정의한다.

### **(1) 청크 분할 전략**

길고 복잡한 문장을 그대로 점자에 표시하는 것이 아니라,  
 다음 기준으로 쪼갠다.

* 의미 단위 기준 분할

  * 예: “증가 / x=2에서 최대 / 이후 감소”

* 길이 제한

  * 3셀로 1\~2번 만에 촉지 가능한 길이로 제한

* 탐색 단위

  * “다음/이전” 버튼으로 이동할 수 있는 단위 기준으로 분리

### **(2) 점자 코드 설계**

3셀의 제한된 자원을 활용하기 위해,  
 다음 요소를 코드로 정의한다.

* 구조 마커: 시작/끝/전환 표시

* 강조 마커: 극값, 중요한 조건 등

* 유형 마커: 지문/선택지/그래프/표 식별

* 관계 마커: 비교·대조·인과 등

이 코드는 하드웨어별로 약간 변형될 수 있으나,  
 핵심은 **의미 정보를 최대한 잃지 않으면서 최소한의 촉각 정보로 압축**하는 것이다.

### **(3) 점자 패킷 생성**

각 청크는 다음과 같은 구조의 패킷으로 변환된다.

* \[타입 코드\] \+ \[내용 코드 시퀀스\] \+ \[구조 마커\]

예:

* (그래프-전반구조) “증가→감소”

* (근거문장) “3문단 2번째 문장”

* (선택지 비교) “① all, ② some”

### **(4) 출력**

* BLE 전송용 점자 패킷 리스트

* 청크 ID, 타입, 순서 정보(음성 출력 동기화용)

## **4.5 학습 로그 기반 개인화 모델 (Learning Log–Based Personalization)**

학습 로그 기반 개인화 모델은  
 시각장애 수험생의 **점자·음성 사용 패턴과 정답/오답 기록**을 바탕으로  
 약점을 분석하고, 이후 학습 흐름을 조정하는 모듈이다.

### **(1) 로그 수집 항목**

* 문제별 풀이 시간

* 점자 청크 재출력 횟수

* 특정 유형(그래프, 추론, 어휘 등)의 오답률

* 음성 명령 패턴 (예: “근거 다시”, “그래프 설명 다시” 많이 부르는 경우)

* 과목별/유형별 히스토리

### **(2) 특징 추출 및 사용자 프로파일링**

로그를 기반으로 다음과 같은 특징을 추출한다.

* 선호 정보 채널: 점자 위주 vs 음성 위주

* 취약 유형: 그래프 해석, 선택지 비교, 어휘·관계어 등

* 인지부하 신호: 재청취/재촉지 빈도, 풀이 시간 증가 구간

* 학습 리듬: 집중 가능한 문제 수, 한 세션 내 적정 난이도 변화

이를 토대로 \*\*사용자 프로파일(user profile)\*\*을 생성 및 지속 업데이트한다.

### **(3) 개인화 전략**

프로파일에 따라 시스템은 다음과 같은 조정을 수행한다.

* 설명 난이도 조절

  * 초반에는 상세 설명, 이후 점점 요약 중심

* 출력 채널 비율 조정

  * 점자를 더 선호하는 경우 점자 청크 비중 증가

* 복습 우선순위 결정

  * 오답률이 높거나 재청취가 많았던 유형 중심으로 복습 큐 구성

* 힌트 제공 패턴 조절

  * “바로 정답”이 아니라 “근거 문장만 먼저 안내” 등

### **(4) 출력**

* 개인별 학습 경로(추천 문제, 추천 복습 리스트)

* 개인화된 점자/음성 출력 설정값

* 누적 리포트(진행도, 약점 변화 등)

이 알고리즘은 시각장애 수험생이 단순히 “정보를 들을 수 있게” 하는 것을 넘어,  
 **개인별 학습 전략을 최적화하는 시각장애 특화 AI 튜터**로 진화할 수 있는 기반을 제공한다.

수능 학습은 이동·휴대 기반 환경에서 이루어지는 경우가 많으며,

  * "3번 선택지 비교",

* **BLE 통신**

  * 점자 청크 전송

  * 점자 디바이스의 버튼 입력 수신

Frontend는 사실상  
 **“사용자 인터페이스 \+ 비선형 탐색 허브 \+ 점자 디바이스 컨트롤러”**  
 역할을 수행한다.

# **5.1.3 Arduino 펌웨어 – BLE 기반 3셀 점자 디바이스**

### **(1) 하드웨어 구성**

* **Arduino Nano / ESP32**

* **BLE(Bluetooth Low Energy) 모듈**

* **3개의 6-dot 솔레노이드 점자 셀**

* **버튼/터치 센서 2\~3개(다음/이전/반복)**

* **리튬 배터리 \+ 충전 회로**

### **(2) Arduino 펌웨어 기능**

* BLE 패킷 수신 → 점자 패턴 파싱

* 각 셀의 솔레노이드 on/off 제어

* 점자 유지 시간/전환 속도 제어

* 버튼 입력을 BLE 이벤트로 PWA에 전송

* 연속 출력 중 과열 방지 제어(스위칭 전류 관리)

### **(3) ESP32를 선택 가능한 이유**

* BLE 통합

* 저전력

* 실시간 인터럽트 처리가 쉬움

* 점자 패턴 전환 latency가 매우 낮음 → 학습 UX 향상

### **(4) 펌웨어 구조**

* setup(): BLE 초기화, 핀 설정

* loop(): 패킷 수신 체크 → 패턴 디코딩 → 셀 구동

* ISR: 버튼 입력 인터럽트 처리

* safetyRoutine(): 과열/전류 관리

점자 디바이스는  
 **“3셀 점자 출력 \+ 사용자 입력 \+ BLE 통신”**  
 **3가지 기능을 모두 갖춘 초소형 학습 장치**로 구현된다.

# **5.2 프론트엔드 구현 상세**

### ***(TTS/STT/BLE 기반 접근성 인터페이스)***

프론트엔드는 React 기반 PWA(Progressive Web App)로 구현되며,  
 시각장애 수험생이 **음성·점자 기반으로 수능특강 PDF를 비선형적으로 탐색**할 수 있도록 설계되었다.

PWA는 다음 세 가지 핵심 기능을 중심으로 구성된다.

1. **TTS 기반 음성 안내 (Audio Output)**

2. **STT 기반 음성 명령 처리 (Voice Commands)**

3. **Web Bluetooth 기반 점자 디바이스 제어 (BLE Control)**

아래에서는 각 기능의 구현 구조와 흐름을 상세히 기술한다.

# **2.1 UI 구조 및 상태 관리**

PWA는 화면을 보지 못하는 사용자를 전제로 하므로,  
 시각적 UI 중심 설계가 아닌 “음성·점자 중심 단계별 내비게이션” 구조로 설계되었다.

### **(1) 주요 페이지**

* **PDF 학습 페이지**

  * 지문 탐색

  * 문항 리스트

  * 선택지 비교

  * 그래프/표 설명

* **점자 장치 관리 페이지(BLE Dashboard)**

  * 디바이스 연결

  * 점자 패턴 테스트

  * 배터리/상태 모니터링

* **학습 로그 페이지**

  * 오답 패턴

  * 재청취/재촉지 기록

  * 개인화 추천

### **(2) 상태 관리**

* Zustand/Recoil 기반 전역 상태 관리

* 상태 저장 항목:

  * 현재 Page/지문 위치

  * 선택된 문항/선택지

  * 현재 점자 청크 ID

  * BLE 연결 상태

  * 음성 입력 활성 여부

  * TTS 큐 상태

이 상태 정보는 **점자 출력과 음성 안내를 동기화**하는 데 핵심 요소다.

# **2.2 TTS 기반 음성 안내 (Text-to-Speech Module)**

### **(1) Web Speech API TTS 사용**

React에서 Web Speech API의 `speechSynthesis`를 활용하여  
 다음 정보를 음성으로 출력한다.

* 지문 핵심 문장

* 문항 설명

* 선택지 비교 청크

* 그래프 의미 설명 청크

* 점자 출력 직전 안내 (“지금 그래프 증가구간을 점자로 출력합니다”)

### **(2) TTS 큐 관리**

길고 복잡한 문장을 한 번에 읽으면 시각장애 수험생이 이해하기 어려우므로,  
 다음 방식으로 음성 출력을 조절했다.

* **청크 단위 TTS 큐 관리**

* TTS 출력 완료 이벤트 → 다음 청크 자동 재생

* STT 명령 수행 시 즉시 TTS 중단

* 점자 출력과 TTS 간 동기화

### **(3) 점자 출력과의 동기화 흐름**

예: “x=2에서 그래프가 최대값을 가진다.”

흐름:

1. TTS가 의미 청크 읽기 시작

2. 백엔드에서 “점자 청크 ID \+ 패턴” 전달

3. PWA가 TTS 종료 이벤트를 감지

4. BLE로 점자 출력

5. 다시 TTS로 “출력 완료” 안내

시각장애인이 **음성 인지 → 촉각 인지** 순서로 자연스럽게 이해하도록 설계됐다.

# **2.3 STT 기반 음성 명령 처리 (Speech-to-Text Module)**

PWA는 시각장애 사용자가 직접 메뉴를 찾지 않아도 되도록  
 \*\*음성 기반 의도 탐색(Voice Intent Navigation)\*\*을 중심으로 설계됐다.

### **(1) Web Speech API STT 사용**

* 연속 듣기 모드(continuous listening) 활성

* 잡음 환경을 고려한 end-of-speech 자동 감지

* “지문 / 문항 / 선택지 / 그래프 / 근거 / 다시 / 다음 / 이전”을 키워드 기반으로 처리

### **(2) 명령 파서(Command Parser)**

사용자 음성 → STT 텍스트 변환 → 명령 파서가 다음과 같이 처리한다.

* "근거 알려줘"  
   → 현재 문항의 근거 문장 청크 요청

* "3번 선택지 비교해줘"  
   → 선택지 비교 알고리즘 → 점자·음성 출력

* "그래프 설명 다시"  
   → 그래프 의미 청크 재출력

* "다음 문항"  
   → 현재 학습 위치 업데이트

* "점자 출력해줘"  
   → BLE 전송 트리거

### **(3) 자연어 의도 분류(LLM 옵션)**

복잡한 문장을 인식할 경우 백엔드 LLM이 명령 유형을 분류한다.

예:

“두 번째 선택지가 왜 틀렸는지 다시 설명해줘”

→ Intent: 선택지 오답 이유 요청  
 → Payload: 선택지 번호=2

# **2.4 Web Bluetooth 기반 점자 디바이스 제어 (BLE Control Module)**

PWA의 핵심 기능은 **스마트폰이 점자 디바이스를 실시간 제어**하는 것이다.

### **(1) BLE 연결 흐름**

1. 사용자가 “점자 장치 연결” 음성 명령

2. PWA → Web Bluetooth API → BLE 장치 스캔

3. 장치 선택

4. GATT 서비스/특성(characteristics) 오픈

5. 점자 출력 스트림 준비 완료

### **(2) 점자 패킷 전송 구조**

패킷 예시 (JSON → binary로 변환):

`{`  
  `"chunk_id": 12,`  
  `"cell1": "101000",`  
  `"cell2": "010100",`  
  `"cell3": "001110",`  
  `"meta": {`  
    `"type": "graph",`  
    `"priority": 2`  
  `}`  
`}`

ESP32/Arduino는 이를 bit 패턴으로 변환해  
 3셀 솔레노이드를 제어한다.

### **(3) BLE 읽기 이벤트**

점자 디바이스의 버튼 입력:

* NEXT

* PREV

* REPEAT

BLE notify 이벤트 → React 상태 업데이트 → TTS/TTS 재동기화.

# **2.5 전체 프론트엔드 동작 흐름 (Unified Interaction Flow)**

시각장애 수험생이 한 문제를 처리하는 실제 흐름은 다음과 같다.

### **1\) 음성 명령 입력 (STT)**

“1번 문항 시작해줘”

### **2\) 백엔드 요청**

문항 구조 \+ 근거 \+ 그래프 의미 청크 요청

### **3\) TTS 안내**

“1번 문항을 시작합니다. 지문 핵심 문장부터 설명합니다.”

### **4\) 점자 출력 요청**

TTS가 끝나면 PWA가 점자 청크 ID에 따라 BLE 전송

### **5\) 사용자 탐색**

* “다음” 버튼 → 다음 의미 청크

* “근거 다시” → 해당 청크 재출력

* “3번 선택지 비교” → 선택지 비교 알고리즘 실행

### **6\) 학습 로그 저장**

모든 상호작용은 백엔드 DB에 기록되어  
 개인화 모델에서 이후 재활용된다.

| 기능 | 기술 | 목적 |
| ----- | ----- | ----- |
| 음성 안내 | Web Speech API TTS | 지문·문항·그래프 의미 설명 |
| 음성 명령 | Web Speech API STT | 비선형 탐색, 근거/선택지/그래프 요청 |
| 점자 제어 | Web Bluetooth | 실시간 점자 출력·버튼 입력 |
| 상태 관리 | React \+ Zustand | 점자/음성 동기화 |
| 접근성 UI | PWA 기반 | 스마트폰만으로 완전한 학습 가능 |

# **5.3 백엔드 구현 상세**

백엔드는 Python/Django 기반 REST API 서버로 구축되었으며,  
 수능특강 PDF를 입력받아 **텍스트·그래프·표·문항·근거·선택지 구조**를 자동 분석한 뒤  
 학습에 필요한 의미 단위(semantic chunk)로 재조합하여  
 프론트엔드(TTS·BLE)에 전달하는 역할을 수행한다.

전체 백엔드는 아래 5개의 핵심 엔진으로 구성된다:

1. **PDF Parser Engine**

2. **OCR & Layout Analyzer**

3. **NLP 지문/문항 의미 분석 엔진**

4. **그래프 의미 분석 엔진 (CV \+ LLM Hybrid)**

5. **Braille Encoding Engine (3셀 점자 압축 변환)**

그리고 모든 연산은 비동기 큐(Celery) 기반으로 처리된다.

3.3 PDF Parser Engine (PyMuPDF / pdfplumber)

### **(1) 페이지 구조 분해**

`class PdfParser:`  
    `def extract_layout(self, pdf_path):`  
        `doc = fitz.open(pdf_path)`  
        `pages = []`  
        `for page in doc:`  
            `text = page.get_text("text")`  
            `blocks = page.get_text("dict")["blocks"]`  
            `images = [img for img in page.get_images()]`  
            `pages.append({`  
                `"text": text,`  
                `"blocks": blocks,`  
                `"images": images`  
            `})`  
        `return pages`

### **(2) 문항/지문 영역 구분**

* 블록의 좌표(x0,y0,x1,y1)를 기반으로

* “문항 번호 패턴(1\~보기), 선택지 패턴(①\~④)” 탐지

* 머신러닝 기반 분류기(LGBM)로 보완

#  **3.4 OCR & Layout Analyzer**

### **(1) OCR 구조**

* Tesseract OCR (수식 인식 제외)

* EasyOCR (표/그래프 내 텍스트 포함)

### **(2) 표(표 1), 선택지(① ② ③) 등 레이아웃 분류**

`class LayoutAnalyzer:`  
    `def detect_choices(self, text_blocks):`  
        `choices = {}`  
        `for b in text_blocks:`  
            `if re.match(r"①|②|③|④", b["text"][:1]):`  
                `choices[b["text"][0]] = b["text"][1:]`  
        `return choices`

 **3.5 NLP 기반 지문/문항 의미 분석 엔진**

### **(1) 지문 논리 구조 분석**

* 문단 분해 → 문장 토큰화

* BERT 기반 문장 중요도 모델 적용

* 핵심 문장 추출 (extractive summarization)

`class PassageAnalyzer:`  
    `def extract_key_sentences(self, sentences):`  
        `scores = self.model.predict(sentences)`  
        `top = sorted(zip(sentences, scores), key=lambda x: x[1], reverse=True)`  
        `return top[:3]  # 핵심 문장 3개`

### **(2) 문항–근거 매핑 알고리즘**

* 선택지/문항 문장 임베딩 → 의미 유사도 계산

* LLM으로 최종 보정

`similarity = cosine(BERT(q), BERT(sentence))`

### **(3) 선택지 논리 구조 분석**

* 정답 선택지 → 근거와 직접 연결

* 오답 선택지 → 오류 유형 분류

  * 단서 불일치

  * 조건 누락

  * 논리 비약

  * 지문 반영X

LLM에게 다음 프롬프트로 구조 분석 요청:

`"다음 선택지를 논리적 근거/오류 기준으로 분해해줘.`  
`출력: {claim, basis, mismatch_reason}"`

 **3.6 그래프 의미 분석 엔진 (CV \+ LLM Hybrid)**

그래프 이미지 → 의미 구조로 바뀌는 핵심 엔진.

### **(1) CV 기반 그래프 구조 추출**

* Hough Transform으로 축 검출

* Canny Edge로 곡선 추출

* 극값/교점 자동 탐지

* y(x) 샘플링 후 monotonicity 검사

예시 코드:

`class GraphAnalyzer:`  
    `def detect_extrema(self, curve):`  
        `# 1차 미분 기반 극값 탐지`  
        `dy = np.gradient(curve["y"])`  
        `extrema = np.where(np.diff(np.sign(dy)))[0]`  
        `return extrema`

### **(2) 의미 요소 생성**

* 증가/감소

* 극값

* 교점

* y절편/x절편

* 두 그래프 비교(면적/위치)

### **(3) LLM 기반 의미 보정**

CV가 추출한 속성을 문항 문맥에 맞게 재표현:

예:

`"이 그래프는 x가 1에서 약간 증가 후 감소하다가 x=4에서 극솟값을 가진다."`

#  **3.7 Braille Encoding Engine (3셀 점자 변환)**

### **(1) 의미 청크 입력 → 점자 코드 변환**

`class BrailleEngine:`  
    `symbolic_map = {`  
        `"increase": "⠮",`  
        `"decrease": "⠯",`  
        `"max": "⠟",`  
        `"min": "⠷",`  
    `}`

    `def encode(self, semantic):`

# **5.4 점자 디바이스 펌웨어 구조 (Braille Device Firmware Architecture)**

점자 디바이스는 **ESP32/Arduino 기반 3셀 점자 모듈**로 구현되며,  
 BLE를 통해 스마트폰 PWA와 통신하고, 수신된 점자 청크를 솔레노이드 핀으로 제어한다.  
 또한, 사용자 버튼 입력(다음/이전/반복)을 다시 BLE로 전송하여  
 **양방향 상호작용**이 가능하도록 설계하였다.

펌웨어는 크게 다음 네 모듈로 구성된다.

1. **BLE 통신 모듈**

2. **점자 셀 제어 모듈 (3셀 × 6점)**

3. **버튼/입력 이벤트 처리 모듈**

4. **메인 루프 및 안전 제어 로직**

## **4.1 하드웨어 구성**

### **(1) 주요 부품**

* ESP32 DevKitC (또는 BLE 내장 보드)

* 3 × 6점 점자 셀 (솔레노이드 혹은 피에조 타입)

* MOSFET/드라이버 보드 (점자 셀 전류 구동용)

* 택트 스위치 2\~3개 (NEXT / PREV / REPEAT)

* 리튬 배터리 \+ 충전 모듈

### **(2) 핀 매핑 예시**

| 기능 | 핀 번호 예시 |
| ----- | ----- |
| Cell1 dot1\~dot6 | 2, 4, 5, 18, 19, 21 |
| Cell2 dot1\~dot6 | 13, 12, 14, 27, 26, 25 |
| Cell3 dot1\~dot6 | 33, 32, 15, 16, 17, 23 |
| NEXT 버튼 | 34 |
| PREV 버튼 | 35 |
| REPEAT 버튼 | 39 |
| BLE | ESP32 내장 |

핀 번호는 보드에 맞게 조정 가능하며, 논문/보고서에는 “예시 구성”으로 적어두면 된다.

## **4.2 펌웨어 전체 구조**

펌웨어는 다음과 같은 구조를 따른다.

`setup():`  
  `- GPIO 초기화`  
  `- BLE 초기화`  
  `- 버튼 인터럽트 등록`

`loop():`  
  `- BLE 수신 버퍼 체크`  
  `- 새로운 점자 패턴이 들어오면 디코딩 → 점자 출력`  
  `- 타이머/안전 제어 수행`

`ISR (버튼):`  
  `- NEXT / PREV / REPEAT 이벤트 플래그 설정`  
  `- BLE notify로 PWA에 전달`

## **4.3 점자 셀 제어 모듈 (Braille Cell Control)**

점자 셀 하나는 6개의 점(dot)으로 구성되며,  
 각 점은 \*\*HIGH(돌출) / LOW(비활성)\*\*로 구동된다.

### **(1) 배열 기반 점 제어 구조**

`// 예: 3셀 × 6점 핀 번호 매핑`  
`const int CELL_PINS[3][6] = {`  
  `{2, 4, 5, 18, 19, 21},      // Cell 1`  
  `{13, 12, 14, 27, 26, 25},   // Cell 2`  
  `{33, 32, 15, 16, 17, 23}    // Cell 3`  
`};`

`void initBraillePins() {`  
  `for (int cell = 0; cell < 3; cell++) {`  
    `for (int dot = 0; dot < 6; dot++) {`  
      `pinMode(CELL_PINS[cell][dot], OUTPUT);`  
      `digitalWrite(CELL_PINS[cell][dot], LOW);`  
    `}`  
  `}`  
`}`

### **(2) 점자 패턴 출력 함수**

패턴은 `"101000"`처럼 문자열 6자리로 온다고 가정한다.

`void setCellPattern(int cellIndex, const String &pattern) {`  
  `for (int i = 0; i < 6; i++) {`  
    `int pin = CELL_PINS[cellIndex][i];`  
    `if (pattern[i] == '1') {`  
      `digitalWrite(pin, HIGH);  // 점 돌출`  
    `} else {`  
      `digitalWrite(pin, LOW);   // 점 비활성`  
    `}`  
  `}`  
`}`

`// 3셀 한 번에 세팅`  
`void setBraillePattern(String cell1, String cell2, String cell3) {`  
  `setCellPattern(0, cell1);`  
  `setCellPattern(1, cell2);`  
  `setCellPattern(2, cell3);`  
`}`

## **4.4 BLE 통신 모듈 (ESP32 BLE Server)**

ESP32는 **BLE GATT 서버**로 동작하며,  
 스마트폰 PWA는 클라이언트로 접속하여 아래 특성을 사용한다.

* **RX Characteristic**: 점자 패턴 수신 (PWA → 디바이스)

* **TX Characteristic**: 버튼 이벤트 전송 (디바이스 → PWA)

### **(1) BLE 초기화 코드 예시 (ESP32 Arduino)**

`#include <BLEDevice.h>`  
`#include <BLEServer.h>`  
`#include <BLEUtils.h>`  
`#include <BLE2902.h>`

`BLEServer *pServer = NULL;`  
`BLECharacteristic *pTxCharacteristic;`  
`bool deviceConnected = false;`

`// 커스텀 UUID (예시)`  
`#define SERVICE_UUID        "12345678-1234-5678-1234-56789abcdef0"`  
`#define CHARACTERISTIC_RX   "12345678-1234-5678-1234-56789abcdef1"`  
`#define CHARACTERISTIC_TX   "12345678-1234-5678-1234-56789abcdef2"`

`class MyServerCallbacks: public BLEServerCallbacks {`  
  `void onConnect(BLEServer* pServer) {`  
    `deviceConnected = true;`  
  `}`  
  `void onDisconnect(BLEServer* pServer) {`  
    `deviceConnected = false;`  
  `}`  
`};`

`class MyCallbacks: public BLECharacteristicCallbacks {`  
  `void onWrite(BLECharacteristic *pCharacteristic) {`  
    `std::string rxValue = pCharacteristic->getValue();`  
    `// 여기서 점자 패턴 디코딩`  
    `handleBraillePacket(rxValue);`  
  `}`  
`};`

`void initBLE() {`  
  `BLEDevice::init("Jeomgeuli-Braille-3cell");`  
  `pServer = BLEDevice::createServer();`  
  `pServer->setCallbacks(new MyServerCallbacks());`

  `BLEService *pService = pServer->createService(SERVICE_UUID);`

  `// TX (Notify)`  
  `pTxCharacteristic = pService->createCharacteristic(`  
                       `CHARACTERISTIC_TX,`  
                       `BLECharacteristic::PROPERTY_NOTIFY`  
                     `);`  
  `pTxCharacteristic->addDescriptor(new BLE2902());`

  `// RX (Write)`  
  `BLECharacteristic * pRxCharacteristic = pService->createCharacteristic(`  
                                          `CHARACTERISTIC_RX,`  
                                          `BLECharacteristic::PROPERTY_WRITE`  
                                        `);`  
  `pRxCharacteristic->setCallbacks(new MyCallbacks());`

  `pService->start();`  
  `pServer->getAdvertising()->start();`  
`}`

## **4.5 점자 패킷 디코딩 로직**

PWA에서 JSON 혹은 단순 문자열 패킷으로 데이터가 온다고 가정하고,  
 여기서는 단순하게 `"101000|010100|001110"` 같은 형식을 예시로 둔다.

`void handleBraillePacket(const std::string &raw) {`  
  `// 예: "101000|010100|001110"`  
  `String payload = String(raw.c_str());`  
  `int first = payload.indexOf('|');`  
  `int second = payload.indexOf('|', first + 1);`

  `String cell1 = payload.substring(0, first);`  
  `String cell2 = payload.substring(first + 1, second);`  
  `String cell3 = payload.substring(second + 1);`

  `setBraillePattern(cell1, cell2, cell3);`  
`}`

실제 구현 시에는

* chunk\_id, type, duration 등 메타데이터를 추가해도 되고,

* JSON 파서를 써도 된다.  
   논문에는 “간단한 패킷 형식 예시”만 들어가도 충분하다.

## **4.6 버튼/입력 이벤트 처리 (NEXT / PREV / REPEAT)**

버튼은 인터럽트 핀에 연결하여 빠르게 처리한다.

`volatile bool nextPressed = false;`  
`volatile bool prevPressed = false;`  
`volatile bool repeatPressed = false;`

`void IRAM_ATTR onNext() {`  
  `nextPressed = true;`  
`}`

`void IRAM_ATTR onPrev() {`  
  `prevPressed = true;`  
`}`

`void IRAM_ATTR onRepeat() {`  
  `repeatPressed = true;`  
`}`

`void initButtons() {`  
  `pinMode(34, INPUT_PULLUP);`  
  `pinMode(35, INPUT_PULLUP);`  
  `pinMode(39, INPUT_PULLUP);`

  `attachInterrupt(34, onNext, FALLING);`  
  `attachInterrupt(35, onPrev, FALLING);`  
  `attachInterrupt(39, onRepeat, FALLING);`  
`}`

### **BLE로 버튼 이벤트 전송**

`void sendButtonEvent(const char *eventType) {`  
  `if (!deviceConnected) return;`  
  `pTxCharacteristic->setValue(eventType); // 예: "NEXT", "PREV", "REPEAT"`  
  `pTxCharacteristic->notify();`  
`}`

`loop()`에서 플래그를 확인해서 BLE로 이벤트를 보낸다.

`void handleButtonEvents() {`  
  `if (nextPressed) {`  
    `nextPressed = false;`  
    `sendButtonEvent("NEXT");`  
  `}`  
  `if (prevPressed) {`  
    `prevPressed = false;`  
    `sendButtonEvent("PREV");`  
  `}`  
  `if (repeatPressed) {`  
    `repeatPressed = false;`  
    `sendButtonEvent("REPEAT");`  
  `}`  
`}`

### **(2) loop()**

`void loop() {`  
  `// ESP32 BLE는 내부에서 이벤트 처리 (delay 짧게)`  
  `handleButtonEvents();`

  `// 필요 시 타이머 기반 안전 제어 (과열 방지, 자동 reset 등)`  
  `delay(5);`  
`}`

필요하다면

* 점자 유지 시간 제한 (예: 5초 후 자동 초기화),

* 연속 구동 시 쿨다운 타임 설정  
   등을 추가해 **솔레노이드 수명과 안전성**도 보장할 수 있다.

## **2\. 기능 구현 상세 (Feature Implementation)**

제안 시스템의 핵심 기능은  
 ① **BLE 기반 점자 디바이스 연결**,  
 ② **수능특강 PDF 업로드 및 파싱**,  
 ③ **그래프·표 처리 모듈**,  
 ④ **LLM 기반 요약 및 학습 전략 생성**  
 으로 구성된다.

각 기능은 프론트엔드(PWA), 백엔드(Django), 하드웨어(ESP32 기반 3셀 점자 디바이스)가 유기적으로 연동되도록 설계하였다.

---

## **2.1 BLE 연결 기능 (BLE Connection & Control)**

### **(1) Web Bluetooth를 이용한 연결 절차**

프론트엔드 PWA는 **Web Bluetooth API**를 사용하여, 브라우저에서 직접 점자 디바이스(ESP32)를 검색·연결한다.

흐름:

1. 사용자가 음성 명령 또는 버튼을 통해 “점자 기기 연결” 실행

2. PWA에서 `navigator.bluetooth.requestDevice()` 호출

3. `SERVICE_UUID` 를 기준으로 **Jeomgeuli-Braille-3cell** 디바이스 검색

4. 연결 후,

   * **RX 특성**: 점자 패턴 송신용(write)

   * **TX 특성**: 버튼 이벤트 수신용(notify)  
      을 오픈하여 통신 채널 형성

### **(2) 점자 패턴 전송**

* 백엔드에서 생성한 점자 청크는  
   `{"cell1": "101000", "cell2": "010100", "cell3": "001110"}`  
   형태의 패턴으로 프론트엔드에 전달된다.

* PWA는 이를 `"101000|010100|001110"`과 같은 문자열로 인코딩하여  
   BLE RX 특성에 write한다.

* ESP32 펌웨어는 패턴을 파싱해 3셀 솔레노이드를 구동한다.

### **(3) 버튼 이벤트 처리**

* 점자 디바이스에는 **NEXT / PREV / REPEAT** 버튼이 탑재되어 있으며,  
   사용자가 버튼을 누르면 ESP32가 `"NEXT"`, `"PREV"`, `"REPEAT"` 같은 이벤트 문자열을 TX 특성으로 notify한다.

* PWA는 이 이벤트를 수신해:

  * 다음 점자 청크 출력,

  * 이전 청크로 이동,

  * 동일 청크 재출력,  
     을 수행하고, 동시에 TTS 안내를 동기화한다.

➡ 이 구조를 통해 스마트폰·점자 디바이스 간에  
 **“점자 출력 ↔ 사용자 입력 ↔ 다음 정보 요청”** 이 실시간 인터랙션으로 이어지도록 구현하였다.

---

## **2.2 PDF 업로드·파싱 기능 (PDF Upload & Parsing)**

### **(1) PDF 업로드 API**

* 프론트엔드에서 사용자가 **수능특강 PDF 파일**을 선택하면,  
   `POST /api/pdf/upload` 엔드포인트를 통해 Django 서버로 전송된다.

* 서버는 파일을 저장하고 **document\_id**를 응답으로 반환한다.

* 분석은 즉시 수행하지 않고, Celery 비동기 태스크로 넘겨서 서버 부하를 분산한다.

### **(2) PDF 파싱 파이프라인**

PDF 파싱은 다음 단계로 이루어진다.

1. **페이지 단위 분해**

   * PyMuPDF/pdfplumber로 각 페이지의 텍스트·이미지 블록 추출

2. **레이아웃 분석**

   * 블록 좌표를 이용하여

     * 지문 영역

     * 문항 번호 영역

     * 선택지 영역(①\~④)

     * 그래프/표 이미지 영역  
        을 구분

3. **텍스트 추출 및 정제**

   * 문단 단위 텍스트 추출

   * 줄바꿈/공백 정리 및 문장 단위로 분할

4. **이미지(그래프·표) 영역 분리**

   * 이미지 블록을 파일로 저장

   * 그래프 분석 엔진에 전달하기 위한 메타데이터(페이지 번호, 좌표, 캡션 텍스트 등) 함께 기록

### **(3) 분석 결과 저장 구조**

* 분석 결과는 다음과 같은 구조로 DB에 저장된다.

* `Document` : PDF 하나

* `Passage` : 지문 단위

* `Question` : 문항 단위

* `Choice` : 선택지 단위

* `Graph` / `Table` : 페이지별 이미지 분석 대상

* `Chunk` : LLM·그래프 엔진을 통해 생성된 의미 단위 청크

이를 통해 프론트엔드는  
 “1번 문항만 요청”, “해당 그래프만 의미 설명 요청” 같은 식으로  
 필요한 부분만 불러와 사용할 수 있다.

---

## **2.3 그래프 처리 기능 (Graph Processing)**

그래프 처리 기능은 **이미지로 존재하는 수학/자료 해석용 그래프를 의미 단위로 변환**하는 역할을 한다.

### **(1) 대상 검출 및 분류**

* PDF 파서가 추출한 이미지 중,

  * 캡션에 “그래프”, “도표”, “(가)\~(나)” 등이 포함되거나

  * 문항 본문에 “그래프를 보고…” 등 표현이 있는 경우  
     → 그래프 후보로 분류

* 이 후보 이미지를 **그래프 분석 엔진**에 전달한다.

### **(2) 그래프 구조 분석**

CV 기반으로:

* 좌표축 검출 (Hough Transform)

* 곡선/막대/점 데이터 영역 추출 (엣지·컨투어 분석)

* 주요 포인트 탐색:

  * 증가/감소 구간 전환점

  * 극대·극소 근사 위치

  * 두 그래프 교차점

  * y절편/x절편

이 결과는 좌표값/구간 리스트와 같은 **정량 정보**로 정리된다.

### **(3) 의미 압축 및 청크화**

* 정량 정보를 그대로 읽어주는 대신, LLM과 결합하여  
   문제 풀이에 필요한 핵심 의미만으로 **문장 형태 청크**를 생성한다.

예시:

* “이 함수는 x가 증가할수록 처음에는 증가하다가, x=2에서 최대값을 가진 뒤 감소한다.”

* “그래프 A는 x\>3에서 항상 그래프 B보다 크다.”

이렇게 생성된 그래프 의미 청크는:

* **TTS용 텍스트**

* **점자용 symbolic 코드(증가·감소·극값 패턴)**

로 다시 분해되어 프론트엔드와 Braille Engine에서 사용된다.

## **2.4 LLM 요약·전략 생성 기능 (LLM Summarization & Strategy Engine)**

LLM 모듈은 단순 요약기가 아니라,  
 **문항 해결을 위한 전략·근거·오답 분석까지 생성하는 “시각장애 특화 튜터” 역할**을 한다.

### **(1) 지문 요약 및 구조화**

입력:

* 지문 전체 텍스트

* 문항 정보(문항 유형, 질문 포인트 등)

LLM에게 다음과 같은 프롬프트 구조로 요청:

* 지문을 “주제–핵심 주장–근거–예시–결론” 구조로 재정리

* 각 부분을 **짧은 청크**단위로 분할

* “문항 N을 풀 때 꼭 봐야 하는 부분”에 우선순위 부여

출력:

* 핵심 문장 리스트

* 요약 청크(점자/음성용)

* 각 문항 관련 근거 위치 정보

### **(2) 문항–근거 매핑 보정**

NLP에서 1차로 계산한 **문항–근거 유사도 결과**를 LLM이 다시 판별:

* “다음 문항을 풀 때 필요한 근거 문장을 지문에서 1\~3개만 골라라.”

* “각 선택지마다 참/거짓 판단에 필요한 지문 부분을 연결하라.”

LLM이 반환한 근거 정보는

* **정답 근거 청크**

* **오답 이유 설명 청크**  
   로 나뉘어 점자·음성으로 제공된다.

### **(3) 학습 전략·힌트 생성**

학습 모드에서는 LLM이 단순 해설 대신 **전략·힌트 중심 출력**을 생성한다.

예:

* “먼저 그래프의 전체 형태를 점자와 음성으로 확인한 뒤, 극값 위치와 증가/감소 구간만 다시 확인해 보세요.”

* “이 문제는 선택지 문장 간의 all/some 차이를 비교하는 유형입니다. ①, ②의 양화사 부분만 점자로 다시 확인해 보세요.”

이 내용은:

* **TTS 안내 스크립트**

* **학습 로그 기반 개인화 전략**

에 반영된다.

## **2.5 정리: 기능 구현 간 상호 연계**

* **BLE 연결**  
   → 점자 디바이스와의 실시간 상호작용 채널을 제공

* **PDF 업로드·파싱**  
   → 수능특강을 구조화된 데이터(지문/문항/그래프/표)로 변환

* **그래프 처리**  
   → 시각적 그래프를 “문제 풀이에 필요한 의미 단위”로 변환

* **LLM 요약·전략 생성**  
   → 시각장애 수험생이 최소한의 정보 처리로 최대한 효율적으로 문제를 풀 수 있도록,  
   **근거·전략·설명**을 자동 생성

이 네 기능이 결합되어,  
 **“수능특강 PDF → 의미 기반 점자·음성 학습 환경”** 이라는  
 본 연구의 전체 목표가 구현된다.

## **3\. DB 설계 (Database Design)**

본 시스템은 수능특강 PDF에서 추출한 지문, 문항, 선택지, 그래프/표, 점자 청크,  
 학습 로그 및 개인화 복습 큐를 저장·관리하기 위해  
 PostgreSQL 기반의 **정규화된 관계형 데이터 모델**을 설계하였다.

데이터베이스는 크게 세 영역으로 구성된다:

1. **문항 구조 저장 영역 (Passage–Question–Choice 구조)**

2. **그래프/표 메타데이터 저장 영역**

3. **학습 로그 및 복습 큐 영역 (Personalization Layer)**

아래에서는 각 영역별 데이터 모델을 상세히 기술한다.

# **3.1 문항 구조 (Passage / Question / Choice Schema)**

문항 구조 모델은 PDF에서 추출된 정보를  
 **지문 → 문항 → 선택지 → 의미 청크**  
 의 계층 구조로 저장한다.

## **(1) Passage (지문)**

| 필드명 | 타입 | 설명 |
| ----- | ----- | ----- |
| `id` | PK | 지문 ID |
| `document_id` | FK | 업로드된 PDF 문서 ID |
| `text` | TEXT | 지문 전체 텍스트 |
| `summary` | TEXT | LLM 기반 핵심 요약 |
| `key_sentences` | JSONB | 핵심 문장 청크 리스트 |
| `page_range` | JSONB | 시작\~끝 페이지 |

→ 지문 분석 및 문항–근거 매핑에 사용됨.

---

## **(2) Question (문항)**

| 필드명 | 타입 | 설명 |
| ----- | ----- | ----- |
| `id` | PK | 문항 ID |
| `passage_id` | FK | 지문 연결 |
| `question_number` | INT | 문항 번호 |
| `text` | TEXT | 문항 텍스트 |
| `difficulty` | FLOAT | 자동 추정 난이도 |
| `skills_required` | JSONB | 문항 해결에 필요한 사고 기술(추론/비교/그래프해석) |
| `evidence_sentences` | JSONB | 근거 문장 매핑 결과 |
| `graph_id` | FK (nullable) | 그래프 기반 문항일 경우 연결 |

→ 점자 청크 생성 시 가장 중요한 정보가 저장되는 곳.

---

## **(3) Choice (선택지)**

| 필드명 | 타입 | 설명 |
| ----- | ----- | ----- |
| `id` | PK | 선택지 ID |
| `question_id` | FK | 문항 연결 |
| `choice_label` | VARCHAR | "①", "②", "③", "④" |
| `text` | TEXT | 선택지 텍스트 |
| `logic_structure` | JSONB | 선택지 논리 구조 분석 결과(주장/조건/근거 등) |
| `error_type` | VARCHAR | 틀린 이유 유형(조건누락/단서불일치/논리비약 등) |
| `is_correct` | BOOLEAN | 정답 여부 |

→ 오답 분석 및 전략 생성에 활용.

---

## **(4) Chunk (의미 청크 – 점자/음성/그래프/근거)**

| 필드명 | 타입 | 설명 |
| ----- | ----- | ----- |
| `id` | PK | 청크 ID |
| `question_id` | FK | 해당 문항 |
| `chunk_type` | VARCHAR | "summary", "evidence", "graph", "choice\_logic" |
| `tts_text` | TEXT | TTS로 읽어줄 문장 |
| `braille_code` | JSONB | 3셀 점자 패턴 배열 |
| `order_index` | INT | 출력 순서 |

→ 프론트엔드가 **비선형 탐색(Next/Prev/Repeat)** 시 사용하는 핵심 데이터.

# **3.3 복습 큐 구조 (Review Queue System)**

시각장애 수험생은 정보 접근성 문제로 인해  
 **오답·재청취·반복 탐색이 매우 중요**하다.  
 이를 위해 **개인화 큐 기반 Adaptive Review System**을 설계했다.

## **(1) ReviewLog (학습 로그)**

| 필드명 | 타입 | 설명 |
| ----- | ----- | ----- |
| `id` | PK |  |
| `user_id` | FK (optional) |  |
| `question_id` | FK |  |
| `timestamp` | DATETIME |  |
| `action_type` | VARCHAR | "correct", "incorrect", "repeat", "braille\_next", "tts\_repeat" |
| `latency` | FLOAT | 반응 시간 |
| `replay_count` | INT | 해당 문항 청크 재청취 횟수 |

---

## **(2) ReviewQueue (복습 큐)**

리뷰 큐는 spaced repetition(간격 반복) 모델을 기반으로 한다.

| 필드명 | 타입 | 설명 |
| ----- | ----- | ----- |
| `id` | PK |  |
| `user_id` | FK |  |
| `question_id` | FK |  |
| `due_date` | DATE | 다음 복습 예정일 |
| `interval` | INT | 복습 간격(1, 3, 7, 15…) |
| `easiness` | FLOAT | 개별 문항 난이도 지수 |
| `stability` | FLOAT | 장기 기억 지표 |

### **큐 업데이트 알고리즘 (SM-2 변형)**

오답 시:

* `interval = 1`

* `easiness -= 0.2`

* `stability 감소`

정답 \+ 빠른 반응 시:

* `interval *= easiness`

* `easiness += 0.1`

이 모델은 시각장애 수험생의 학습 특성(반복 탐색, 근거 재청취)을 반영하여 조정하였다.

---

## **요약: DB 설계의 핵심 기여**

* **지문–문항–선택지–그래프** 구조를 그대로 반영한 ERD

* 그래프 분석 결과를 의미 단위까지 분해해 저장하는 메타데이터 스키마

* 시각장애 수험생의 학습 패턴에 특화된 **개인화 복습 큐 모델**

* 점자·음성 안내를 위한 **청크 단위 구조 저장**

이 DB 설계는 PDF → 구조 분석 → 의미 분석 → 점자 출력 → 개인화 학습  
 전체 파이프라인을 완결적으로 뒷받침한다.
